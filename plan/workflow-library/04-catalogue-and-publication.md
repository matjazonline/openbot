# Step 4 — Global Catalogue and Publication

## Outcome and dependencies

Operators can author and publish immutable workflow packages; company users can discover compatible
published releases. Depends on [package validation](02-package-schema.md) and
[persistence](03-persistence-and-ports.md).

## Implementation

1. Add operator-authorized create/edit/validate/publish/retire commands. Move reusable operator
   authorization behind an application-consumed policy if necessary; do not assume a route check
   protects calls from another adapter. All edits carry expected draft version and command ID.

2. Allow an operator draft to select global agent/skill sources and configure package-local roles,
   connection requirements, setup fields, trigger presets, and synthetic examples. Restrict source
   lookup to the global library. Published content cannot contain data copied from company runs,
   private messages, memory documents, or credentials.

3. Publication loads a coherent source snapshot: lock the draft and referenced global components
   in a documented stable order, validate source hashes, resolve all presets, and run package/SOP
   validation. If normalization occurs before the transaction, reload and compare every source
   hash under locks at commit; a stale preview conflicts. Do not call an LLM or provider in this
   transaction. Freeze the package, switch the template's published pointer, and append the event
   and command receipt atomically.

4. Store an explicit capability requirement summary generated by the validator. Catalogue reads
   show required business tools, human roles, available start methods, expected output, and setup
   prerequisites. A compatibility summary is advisory until company-specific setup validation.
   Unsupported releases may remain visible with a reason but cannot be installed or activated.

5. Add keyset-paginated reads for published templates and version detail. Expose curated metadata
   and inspectable published instructions to authenticated company users; drafts and source
   management remain operator-only. Installation counts, company customizations, connection
   accounts, and case results never enter the global catalogue response.

6. Use repository-owned, typed/validated package fixtures and an explicit catalogue import command
   for product-supplied content. Stable `(template_slug, release_number, content_hash)` determines
   import idempotency. Reimport of the same release/hash is a no-op; changed bytes under the same
   release fail. Do not update published rows or company installations during application startup.
   The existing built-in agent installer remains available independently.

7. Define retirement precisely: remove a release from new setup/install/adoption eligibility,
   invalidate pending setup previews that target it, and preserve already installed revisions and
   existing runs. A global retirement is not a tenant-wide runtime kill switch. Disabled platform
   capabilities and revoked company permissions still stop their respective runtime operations.

8. Add narrow routes, for example `/api/workflow-library` for published reads and an explicitly
   operator-scoped management surface for drafts/publication. Apply request-size limits, normal
   browser mutation protections, bounded search/filter fields, and safe identifier-only tracing.

## Verification and acceptance

- Two publishers racing on one draft produce one published release and one event sequence.
- Publication racing with a source skill/agent edit either uses one coherent version of all
  dependencies or returns a stale-preview conflict; it never stores a torn package.
- Import twice is idempotent; altered content at an existing release number is rejected.
- A company member cannot author a global package, read a global draft, or discover tenant data
  through catalogue filters, detail pages, or errors.
- Retiring a version blocks new installation while an existing installed fixture still resolves
  identical frozen bytes.
- Accept when catalogue publication is reproducible and consumers need no live global component
  lookup to inspect or install a release.
