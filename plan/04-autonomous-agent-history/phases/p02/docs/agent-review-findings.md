- **Evidence:** D1 section “Exhaustive failure/cancellation and monotonic stamps” terminalizes queued/active exchanges on workflow run failure while reusing the existing lifecycle contracts; section “Before-provider capture” requires retry of the same execution to reuse its exchange/order. Accepted `AgentExchangeState::permits` (`src/application/workflow/agent_history/contracts.rs:62–75`) makes Failed terminal. But `control_retry::retry_on` (`src/adapters/persistence/workflow/control_retry.rs:3–43`) deliberately accepts a retry-safe **failed** root, reopens the same job/execution, and changes the same run back to running. Native `workflow_control_retry_safe` (`migrations/20260817000000_init_schema.sql:2876–2912`) requires an unfinished execution and preserved retry budget, explicitly describes agent checkpoint resume, and excludes only specific exhausted/invalid/repeated-call failures—not every agent failure. `recovery::retire_on/settle_run` (`recovery.rs:21–100,195–211`) can produce failed roots without committing an execution final_error when no error route exists. The native predicate and generic retry writer apply equally to eligible agent executions meeting those conditions.
- **Impact:** after the proposed failure hook, a currently permitted operator retry will encounter its unique exchange permanently Failed. It cannot legitimately reopen or complete under the proposed state contract, and allocating another row/position would violate logical-execution identity. Broadening the failed-state update without defining turn/retention implications would instead invalidate terminal assumptions and future successor ordering. This conflicts with original02B4–6, original01 same-activation retry invariants, and original03/06 existing safe recovery ownership.
- **Required correction:** reconcile the decision's notion of final exchange failure with the actual retry-safe failed-root lifecycle before implementation. Specify how existing authorized same-execution operator retry preserves exchange identity, original input/provenance, checkpoint, counters and ordering semantics while genuine terminal cancellation/expiry/exhaustion still settles work. Define any necessary state/terminalization distinction and its native evidence; do not silently disable existing safe retries, create a second exchange, reset spent budgets, or add an unrestricted resurrection path. State the phase03 turn/phase06 lifetime consequences sufficiently to avoid an incompatible schema now, without claiming those phases implemented. Add a focused genuine agent.run regression covering enqueue/checkpoint, a retry-safe failed root, existing retry command, same exchange/order/input/checkpoint and successful final acceptance; assert current authority/stale fencing and truly terminal refusal as appropriate. Keep original retry/accounting/continuation assertions.
- **Instruction lesson:** workflow terminal labels and immutable exchange terminal states are not equivalent where the existing owner supports explicit recovery. Candidate scoped guidance: before wiring durable child records to a parent status transition, trace both transition and authorized reopen paths, including SQL predicates and operator commands. This extends the lifecycle inspection lesson from p01; no AGENTS/skill edits authorized.
- **Resolution:** **OPEN** on AH-P02-AG1-R1. No phase02 architecture PASS or dependent implementation acceptance. Revised decision and affected recheck required; unchanged source/schema aspects can reuse this round's coverage.

## AH-P02-B1-F2 — ambiguous checkpoint reopen can falsely acknowledge missing reactivation

- **Context:** same date/workflow/reviewer/worktree/HEAD/source/coordination as AH-P02-B1-F1; whole-code round AH-P02-B1-R1. [Round note](agent-review-notes.md#ah-p02-b1-r1--whole-phase-code-review-changes-required), [REVIEW](REVIEW.md), [TASK](TASK.md).
- **Classification:** actionable correctness/recovery defect, **medium**, with an associated targeted-verification gap.
- **Evidence:** `checkpoints::open_on` (`checkpoints.rs:391–405`) now attaches/re-activates an existing checkpoint's Queued exchange and correctly commits that mutation even though the checkpoint result is AlreadyApplied. But `open_workflow_checkpoint`'s `Attempt::Ambiguous` resolver (`checkpoints.rs:78–98`) still only loads the pre-existing checkpoint and calls `matching(saved,spec)`, returning `Evidence::Applied(AlreadyApplied(...))` without checking the exchange/link/state. `WriteBound::commit/attempt` (`persistence_bound.rs:217–226,263–295`) enters ambiguous resolution for transport/timeout uncertainty during COMMIT, including a commit that did not apply. A pre-existing matching checkpoint therefore does not prove the new Queued→Active mutation committed.
- **Impact/reproduction condition:** use the genuine safe-control-retry path to leave the old checkpoint present and the same exchange Queued. Lose the reopen commit before it applies while its outcome is uncertain. The resolver can report success from the old checkpoint although the exchange remains Queued. Subsequent fresh execution/model admission requires Active and refuses, so provider-entry safety is retained, but legitimate recovery receives a false success and can fail rather than accurately retry the missing mutation. Root independently confirmed there is no other durable reactivation proof in this resolver. This is a supported source-level counterexample, not a reviewer-executed transport fault.
- **Verification gap:** `agent_history_completion_competing_finalizers_and_lost_ack_keep_one_answer` (`agent_history_completion_tests.rs:57–91`) runs competing successful updates and ordinary duplicate replay; it does not inject transport/COMMIT ambiguity. The deferred-constraint rollback test at94–116 proves known failure/rollback, not this ambiguous existing-checkpoint mutation. Retain these useful tests but do not represent them as actual ambiguous-reopen coverage.
- **Required correction/evidence:** reconcile the entire new reopen effect under current ownership: a durable matching checkpoint alone is insufficient when exchange activation may be missing. The read-only resolution must return an accurate applied/not-applied/unresolved result for the checkpoint plus required exchange state/link, without performing a second writer or treating a legitimate completed replay as newly active work. Add focused actual fault injection around existing-checkpoint reactivation, proving both committed/lost-ack and not-applied/ambiguous outcomes, same ID/order/checkpoint/counters, no duplicate provider call, stale/current authority refusal, and successful subsequent recovery. Exercise actual enqueue/final acknowledgement boundaries as required by original02 rather than relying solely on duplicate replay naming.
- **Instruction lesson:** extending an idempotent operation with a new side effect changes its evidence of success. Candidate scoped guidance: review ambiguous-commit readbacks whenever an AlreadyApplied path starts committing additional state; prove all newly added effects, not only the old receipt. No instruction edit authorized.
- **Resolution:** OPEN on AH-P02-B1-R1. Source remains frozen. Root acknowledged the resolver gap and the test coverage distinction; correction/recheck required.
