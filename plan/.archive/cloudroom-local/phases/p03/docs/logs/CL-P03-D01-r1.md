## Ownership and lifecycle

Extend the existing application local-agent boundary and Postgres machine/lease store; Axum/WebSocket types stay in the HTTP adapter. Add Axum ws feature with the committed Cargo lockfile. GET /v1/local-machines/connect accepts only a single bounded Bearer machine credential plus installation/protocol headers; URLs carry no credential. Existing machine-generation verifier establishes identity before parsing peer messages. Reject unknown versions and invalid/revoked identity. Pairing credentials cannot become user sessions or general API authority.

One short database lease per machine, replacing generation atomically as p02 already implements. Every poll, attempt marker, observation and acknowledgment checks company/machine/installation/credential generation/connection generation/owner/live expiry. Presence remains separate from enabled/disabled/revoked. Old close/release cannot clear a replacement. Recheck the fence after the bounded hello and before any saved work is emitted. Revocation or renewal loss closes reachable sockets; there is no claim of physical native stop.

One adapter owner retains all connection futures in a tracked lifecycle and a global admission semaphore (fixed 32 connections/replica). Reserve tracking before handing work to Axum's upgrade callback so shutdown cannot miss an accepted-but-not-started callback. Each connection uses one supervised select loop, avoiding separately detached reader/writer/heartbeat tasks. Select/cancel covers actual reads/writes and DB waits. Stop admission and cancel sockets at server shutdown, then join them within a fixed drain; every network/DB step has its own shorter timeout. Integrate with main serve's existing shutdown owner, including server-error shutdown. No in-memory routing registry or sticky sessions. Poll durable rows in small batches (notification hints optional), heartbeat 15s, lease stale 45s, handshake 10s.

## Wire framing and bounded assembly

Closed version-1 logical envelopes carry authenticated installation/connection identities. Company/machine identity always derives from the server fence. Commands contain the frozen typed LocalAgentOperation (its canonical deadline string is preserved verbatim by Node). Unknown fields/kinds/versions fail; no dual decoder. Sequence/generation values sent to JS must be safe integers, otherwise refuse rather than round precision.

Use bounded transport chunks for both directions, so even a legal 32KiB prompt with JSON escaping fits the 64KiB physical-message limit. A logical message is serialized once, hashed over its exact bytes, and divided into at most 16KiB byte chunks (base64 inside a closed JSON frame). Each frame includes protocol, transfer identity, index/count/total bytes and SHA-256. Validate encoded length/count/size before allocating or decoding. At most one assembly per direction/connection, maximum 2MiB serialized logical message, 30s assembly deadline. Enforce physical frame/message 64KiB and outgoing serialization bounds. Bounded catalogs that exceed the logical message budget are explicitly refused; result text remains 256KiB and prompt 32KiB. These are independent bounds, not a promise every maximal combination fits.

Partial transport chunks are not acknowledged journal observations. Keep them only in bounded connection-owned memory; drop on timeout/disconnect. The plugin retains the complete durable logical observation until an acknowledgment after full validation and database commit. A server crash mid-assembly therefore redelivers the same immutable observation; it does not lose acknowledged bytes or require a scratch chunk table. On complete assembly, verify length/digest, parse the closed bounded typed message, and persist the entire observation/output before acknowledgment. Sequence reuse binds exact original serialized bytes; the plugin journal preserves that serialization for replay rather than reserializing through unordered data. Small messages use the same framing; avoid another decoder.

## Immutable commands, authority and cancellation

The application port admits an operation under a bounded stable logical invocation key and exact frozen command/deadline/digest. Same invocation identity returns the saved operation only when immutable inputs agree; conflicting identity/digest is rejected. Serialize per-machine capacity using the same machine lock: max 8 unsettled effects and 32 queued operations, reserving 8 control slots. An operation never migrates to another machine/thread. A session must resolve its original conversation/workflow association; a manager's access to a machine alone does not grant output authority.

At first delivery, lock live company/actor authority and the saved association before machine/operation locks. Check machine/project/catalog, exact frozen provider/model/reasoning, approvals where applicable, run state and absolute deadline. Do not hold a DB transaction across socket I/O. Commit delivery_attempted_at before the first write, including the first chunk. If ownership is lost after that commit, delivery may be ambiguous; stable identities and the plugin journal handle it. Before that marker, withdrawal/expiry is a definitive pre-dispatch refusal; afterwards retain uncertainty/reconciliation and do not blindly retry the SDK. Disable prevents new dispatch while allowing observation/recovery of accepted work; revoke invalidates credentials/ownership atomically as in p02. Stop/archive are separate explicit controls, never replacement outcomes for a prompt.

Workflow admission/required-approval parking remains a p05 producer. p03 must expose a safe seam and must not accept an unverified workflow-origin command as authorized. The p05 integration must add its current-fence/live-approval recheck and atomic parking/wake in the same responsible persistence boundary before the handler is enabled. p03 tests cover manual/association and refusal semantics without claiming workflow execution exists.

## Journal recovery and observation commit

Bind a durable journal identity to the installation. Initial empty installations may bind; changed/missing journal after possible delivery or mapped sessions is recovery-required, never ready to repeat effects. Preserve old server evidence and require explicit repair rather than silent rebind. Hello's journal high-water mark must not be below the server's durable acknowledgment. A reconnect starts reconciling: replay previously attempted outstanding operations before untouched effect commands. The plugin recovers command journal entries and mapped threads first; server Ready is conditional on current-generation reconciliation evidence for outstanding attempted operations. Missing local entries yield uncertainty, never a new spawn.

Journal observations carry stable positive sequence, operation ID and closed receipt/submission-intent/native turn/control/catalog/uncertain evidence. Receipt means durable local acceptance, not SDK success. Validate the saved installation/session/command and evidence transitions; native thread/turn must match or establish the command's immutable mapping. A human's interleaved turn cannot settle an Openbot prompt. Thread controls must name the mapped thread; catalog evidence cannot settle a thread command. Enforce per-operation frozen provider/project/model and prevent one effect turn from settling multiple operation identities.

Transactions serialize the machine cursor and operation update: deduplicate same sequence/same immutable digest, reject changed reuse and gaps, save accepted evidence/bounded output/mapping/outcome, advance contiguous acknowledgment, then commit. Acknowledgment is emitted only after commit. Replay after a lost acknowledgment cannot create a second state transition/publication. Server cancellation/expiry is not undone by late data; retain it as audit evidence. Positive SDK reconciliation may resolve uncertainty when still permitted, without resubmission. p05 attaches any workflow wake-up/continuation in this transaction under its current-fence rules; no generic wait.event spoofing or callback outside the transaction. Until that integration exists no p03 claim implies a workflow can resume.

Expire queued waits using database time and bounded sweeps. Expiry after possible delivery ends the Openbot wait and records uncertainty about local execution; it never claims an offline process stopped. Retained observation/output data and durable cursor survive socket/replica loss. p06 supplies bounded retention without deleting unacknowledged journal identities or live work.
