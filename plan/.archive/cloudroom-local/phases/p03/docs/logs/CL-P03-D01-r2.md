## Ownership and lifecycle

Extend the existing application local-agent boundary and Postgres machine/lease store; Axum/WebSocket types stay in the HTTP adapter. Add Axum ws feature with the committed Cargo lockfile. GET /v1/local-machines/connect accepts only a single bounded Bearer machine credential plus installation/protocol headers; URLs carry no credential. Existing machine-generation verifier establishes identity before parsing peer messages. Reject unknown versions and invalid/revoked identity. Pairing credentials cannot become user sessions or general API authority.

One short database lease per machine, replacing generation atomically as p02 already implements. Every poll, attempt marker, observation and acknowledgment checks company/machine/installation/credential generation/connection generation/owner/live expiry. Presence remains separate from enabled/disabled/revoked. Old close/release cannot clear a replacement. Recheck the fence after the bounded hello and before any saved work is emitted. Revocation or renewal loss closes reachable sockets; there is no claim of physical native stop.

One adapter owner retains all connection futures in a tracked lifecycle and a global admission semaphore (fixed 32 connections/replica). Reserve tracking before handing work to Axum's upgrade callback so shutdown cannot miss an accepted-but-not-started callback. Each connection uses one supervised select loop, avoiding separately detached reader/writer/heartbeat tasks. Select/cancel covers actual reads/writes and DB waits. Stop admission and cancel sockets at server shutdown, then join them within a fixed drain; every network/DB step has its own shorter timeout. Integrate with main serve's existing shutdown owner, including server-error shutdown. No in-memory routing registry or sticky sessions. Poll durable rows in small batches (notification hints optional), heartbeat 15s, lease stale 45s, handshake 10s.

## Wire framing and bounded assembly

The credential-authenticated bounded Hello is the only pre-session message and performs no operation/observation action. After the server rechecks the lease and returns Welcome with the current identity, every version-1 command/observation/Ready/acknowledgment envelope carries authenticated installation/connection identity. Company/machine identity always derives from the server fence. Commands contain the frozen typed LocalAgentOperation (its canonical deadline string is preserved verbatim by Node). Unknown fields/kinds/versions fail; no dual decoder. Sequence/generation values sent to JS must be safe integers, otherwise refuse rather than round precision.

Use bounded transport chunks for both directions, so even a legal 32KiB prompt with JSON escaping fits the 64KiB physical-message limit. A logical message is serialized once, hashed over its exact bytes, and divided into at most 16KiB byte chunks (base64 inside a closed JSON frame). Each frame includes protocol, transfer identity, index/count/total bytes and SHA-256. Validate encoded length/count/size before allocating or decoding. At most one assembly per direction/connection, maximum 2MiB serialized logical message, 30s assembly deadline. Enforce physical frame/message 64KiB and outgoing serialization bounds. Bounded catalogs that exceed the logical message budget are explicitly refused; result text remains 256KiB and prompt 32KiB. These are independent bounds, not a promise every maximal combination fits.

Partial transport chunks are not acknowledged journal observations. Keep them only in bounded connection-owned memory; drop on timeout/disconnect. The plugin retains the complete durable logical observation until an acknowledgment after full validation and database commit. A server crash mid-assembly therefore redelivers the same immutable observation; it does not lose acknowledged bytes or require a scratch chunk table. On complete assembly, verify length/digest, parse the closed bounded typed message, and persist the entire observation/output before acknowledgment. Transport chunk integrity hashes the complete current envelope bytes. Durable journal dedup hashes only canonical typed observation payload bytes, as defined below; a reconnect may change the transport envelope/hash without changing the journal identity. Small messages use the same framing; avoid another decoder.

## Immutable commands, authority and cancellation

The application port admits an operation under a bounded stable logical invocation key and exact frozen command/deadline/digest. Same invocation identity returns the saved operation only when immutable inputs agree; conflicting identity/digest is rejected. Serialize per-machine capacity using the same machine lock: max 8 unsettled effects and 32 queued operations, reserving 8 control slots. An operation never migrates to another machine/thread. A session must resolve its original conversation/workflow association; a manager's access to a machine alone does not grant output authority.

At first delivery, lock live company/actor authority and the saved association before machine/operation locks. Check machine/project/catalog, exact frozen provider/model/reasoning, approvals where applicable, run state and absolute deadline. Do not hold a DB transaction across socket I/O. Commit delivery_attempted_at before the first write, including the first chunk. If ownership is lost after that commit, delivery may be ambiguous; stable identities and the plugin journal handle it. Before that marker, withdrawal/expiry is a definitive pre-dispatch refusal; afterwards retain uncertainty/reconciliation and do not blindly retry the SDK. Disable prevents new dispatch while allowing observation/recovery of accepted work; revoke invalidates credentials/ownership atomically as in p02. Stop/archive are separate explicit controls, never replacement outcomes for a prompt.

Workflow admission/required-approval parking remains a p05 producer. p03 must expose a safe seam and must not accept an unverified workflow-origin command as authorized. The p05 integration must add its current-fence/live-approval recheck and atomic parking/wake in the same responsible persistence boundary before the handler is enabled. p03 tests cover manual/association and refusal semantics without claiming workflow execution exists.

## Journal recovery and observation commit

Bind a durable journal identity to the installation. Initial empty installations may bind; changed/missing journal after possible delivery or mapped sessions is recovery-required, never ready to repeat effects. Preserve old server evidence and require explicit repair rather than silent rebind. Hello's journal high-water mark must not be below the server's durable acknowledgment. A reconnect starts reconciling: replay previously attempted outstanding operations before untouched effect commands. The plugin recovers command journal entries and mapped threads first; server Ready is conditional on current-generation reconciliation evidence for outstanding attempted operations. Missing local entries yield uncertainty, never a new spawn.

Journal observations carry stable positive sequence, operation ID and closed receipt/submission-intent/native turn/control/catalog/uncertain evidence. Installation ownership is established by the authenticated current envelope, not by adding a volatile generation to the journal payload. Receipt means durable local acceptance, not SDK success. Validate the saved installation/session/command and evidence transitions; native thread/turn must match or establish the command's immutable mapping. A human's interleaved turn cannot settle an Openbot prompt. Thread controls must name the mapped thread; catalog evidence cannot settle a thread command. Enforce per-operation frozen provider/project/model and prevent one effect turn from settling multiple operation identities.

Transactions serialize the machine cursor and operation update: deduplicate same sequence/same canonical observation-payload digest (never envelope bytes), reject changed reuse and gaps, save accepted evidence/bounded output/mapping/outcome, advance contiguous acknowledgment, then commit. Acknowledgment is emitted only after commit. Replay after a lost acknowledgment cannot create a second state transition/publication. Server cancellation/expiry is not undone by late data; retain it as audit evidence. Positive SDK reconciliation may resolve uncertainty when still permitted, without resubmission. p05 attaches any workflow wake-up/continuation in this transaction under its current-fence rules; no generic wait.event spoofing or callback outside the transaction. Until that integration exists no p03 claim implies a workflow can resume.

Expire queued waits using database time and bounded sweeps. Expiry after possible delivery ends the Openbot wait and records uncertainty about local execution; it never claims an offline process stopped. Retained observation/output data and durable cursor survive socket/replica loss. p06 supplies bounded retention without deleting unacknowledged journal identities or live work.

## D01-F1 correction: separate current transport authority from immutable journal content

This section is normative and resolves CL-P03-D01-F1 from gate round CL-P03-D01-R1. There are two separate byte identities:

1. **Transport identity/integrity:** the framed current envelope contains version, installation, credential generation and connection generation plus its message. Its complete serialized bytes and SHA-256 identify one transfer only. A new connection is allowed and required to re-encode this envelope with the new server-issued identity. These volatile fields and the chunk transfer identity/digest never enter journal deduplication.
2. **Durable journal content:** a typed LocalAgentObservation (sequence, operation_id, closed evidence) is immutable. The server derives its durable SHA-256 from `serde_json::to_vec(&observation)` after strict decoding, using the concrete Rust type's stable field/variant order. That canonical typed payload excludes connection metadata. SQL local_agent_observations stores this payload digest and the decoded payload; a peer-provided checksum never substitutes for server calculation. Representational object key order/whitespace in a transport envelope does not change the typed canonical content. Changing a sequence's operation/evidence/output changes its canonical content and must conflict. The plugin durably stores the frozen journal payload and sequence; it may wrap that same payload under a new current envelope when reconnecting. No field migration or schema/version fallback.

On every observation, first require the envelope identity to equal the socket's authenticated fence, then recheck that entire fence and live database lease in the same transaction as inbox lookup/dedup/cursor advancement. **Deduplication never bypasses current authentication/fencing.** Example: generation N commits sequence S but its ACK is lost. Generation N+1 replaces it. Replaying the unchanged observation S in envelope N+1 yields the same stored payload digest and current highest durable ACK; sending it in envelope N is refused even though S/digest are known. A current envelope carrying changed content under S conflicts and cannot advance the cursor or alter prior output. Old socket cleanup still cannot release N+1.

The Hello is authenticated by the credential/header-acquired fence and its own bounded installation/protocol/journal checks, but carries no yet-unknown server connection generation. The server rechecks ownership before Welcome; after Welcome all peer operational envelopes must echo the returned current identity. No pre-Welcome operation, observation or Ready is accepted. This avoids a circular requirement for the client to know its generation before the server issues it.

Command payload_digest keeps the existing p01/p02 definition: SHA-256 over canonical typed `(command, exact canonical deadline)` bytes. Rewrapping a command in a new connection envelope or transfer does not mutate the command or its digest. CL-C002/r2 exact deadline strings remain unchanged.

**Discriminating proof:** real DB/WS lost-ACK commit followed by reconnect must show (a) unchanged payload under N+1 returns the original receipt/highest ACK and does not duplicate state/output, (b) the old N envelope is rejected before inbox dedup or cursor/state mutation, (c) changed payload under the same S fails under an otherwise-valid N+1 fence. Also a typed canonical-payload test proves changing only the envelope changes transfer integrity but leaves the journal digest unchanged. These are additional assertions in AC1/AC3/AC4, not fixture execution claimed at the gate. Prior reviewed invariants are unchanged.
