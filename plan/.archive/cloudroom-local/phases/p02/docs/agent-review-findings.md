## CL-P02-D02-F1 — reject or explicitly resolve leap-second deadlines before freezing

- **Status:** OPEN, 2026-11-07. Actionable correctness/architecture defect, medium severity. Origin: proposed CL-P02-D02/r1; gate round [CL-P02-D02-R1](agent-review-notes.md#cl-p02-d02-r1--precision-correction-gate). Workflow `implement-astra-reviewed-2-2`, p02, reviewer `/root/cloudroom_reviewer`, requested Astra/high (actual metadata unavailable). Worktree `/Users/mac03/dev/openbot`, base/HEAD `97e5d60dc538e26c7cb976a8d63772eed80baff2`; source digest `e707ccc09d026a257ace8fa7f7837af425564736dc3ccac9e6f25942d842372e`. [TASK](TASK.md), [REVIEW](REVIEW.md).
- **Evidence:** [Decision r1](logs/CL-P02-D02-r1.md) defines constructor truncation and decoder refusal specifically for submicrosecond precision. Chrono also accepts leap-second values with `nanosecond() >= 1_000_000_000`; e.g. `2026-11-07T22:00:60.123456Z` is already microsecond aligned, so that proposed rule leaves it unchanged. This is not limited to actual announced UTC leap seconds: chrono permits syntactic leap-second input without validating historical occurrence (`chrono-0.4.45/src/naive/time/mod.rs:68–71,210–211,405–432`). `sqlx-postgres-0.8.6/src/types/chrono/datetime.rs:36–60,77–80` encodes DateTime by subtracting the non-leap Postgres epoch and taking integer microseconds, then decodes by adding that duration back to the ordinary epoch. The leap-second representation is not retained. `src/domain/local_agents/operations.rs:98–106,171–176,230–246` hashes the serialized DateTime and checks the hash on recovery. Consequently, a microsecond-aligned leap-second deadline can still change serialized bytes after persistence and fail the frozen digest check. The 24-hour admission window alone does not reject such a syntactically representable future value.
- **Required correction:** State how leap-second/nonrepresentable timestamp inputs are handled before immutable hash freeze, and require record decoding to reject any forbidden representation even with a matching forged digest. A narrow rejection policy is sufficient; no compatibility machinery is needed. Add typed constructor and matching-digest decoder cases for a whole-microsecond leap-second value, with persistence coverage if the chosen policy admits any transformed value. Preserve the stated bound on how much ordinary nanosecond truncation can shorten a deadline.
- **Verification:** Source-backed finding; reviewer ran no native/DB/runtime operation. The author's pending ordinary `.123456789` regression does not cover this distinct representation. Dependency paths are under `/Users/mac03/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/`.
- **Instruction lesson:** The existing cross-boundary representability invariant is sufficient; the decision considered fractional resolution but omitted another admitted representation. No repository instruction change proposed from this single case.
- **Resolution history:** 2026-11-07 initially open against decision r1. Requires revised decision and gate recheck before dependent normalization edits.
