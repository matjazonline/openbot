# CL-P02-D02/r2 — stable operation deadlines across storage and wire

Original p01 01B requires immutable command/deadline/digest; p02 persists those operations; p03/p04 recover and compare the same digest across restart/redelivery. Accepted p01 artifact cfc3dd8052971597cce455f3c7013a5051c0abb74aed605b490017c547d93233 remains historical evidence. This revised decision resolves CL-P02-D02-F1 from gate round R1. It is a proposed shared-contract correction in p02, not a rewriting of that phase's review.

## Contradicted assumption and evidence

LocalAgentOperation::queued stores an arbitrary chrono DateTime<Utc>; PayloadDigest::calculate serializes command and that deadline. OperationRecord decoding recomputes that hash. PostgreSQL timestamptz stores microsecond resolution, whereas chrono admits nanoseconds. Reading the same persisted operation can therefore change the serialized deadline and invalidate its frozen digest even though nobody edited its inputs.

`deadline-precision-repro.txt` demonstrates the real owned PostgreSQL 18 value loses the original fractional precision. New production-path test `cloudroom_company_operation_deadline_round_trip_preserves_digest` constructs a future .123456789 deadline, writes the actual domain command/hash/deadline to local_agent_operations, reads the real row and decodes LocalAgentOperation. Its pre-fix execution failed exactly with operation payload digest mismatch; retained immutable output is deadline-roundtrip-before.txt. No passing result is asserted yet. No production normalization change has been applied.

## Decision

Define operation deadline resolution as microseconds in the inner contract, without introducing SQL/SDK types into it. Reject Chrono leap-second representations (timestamp_subsec_nanos >= 1,000,000,000) before any normalization or hashing. Then the queued constructor truncates finer fractions before freezing/hash calculation. A single private canonical-deadline helper owns these rules; the record decoder requires that its input already equals the canonical result. There is no silent conversion of a leap second to another instant. The record decoder rejects leap seconds and nonrepresentable submicrosecond deadlines even when an input supplies a matching digest; it does not silently rewrite a frozen stored record. Chrono's canonical UTC serialization (Z and its normal 0/3/6 fractional digits) remains the hashed representation. The change shortens a supplied deadline by less than one microsecond; admission still validates the final frozen deadline against now and the 24-hour maximum.

Keep the same p01 command+deadline digest algorithm. Rust typed serialization defines field order; after loading JSONB, typed decoding restores that order. JavaScript peers preserve the exact server deadline string when checking the command/deadline digest. They may parse it to compare time, but must not replace it with Date.toISOString(), which loses microseconds. p03/p04 must add cross-language fixtures for the actual wire serializer before dispatch exists.

No backfill, legacy decoder or dual representation. Reset the task's owned databases where necessary. No existing deployed data is preserved by this repository. Corrected p02 review covers the change and affected p01 tests; p01's historical pass is not silently reissued for changed source.

## Invariants/failure behavior

- Identical admitted command/deadline bytes have an identical digest before and after real persistence and restart.
- Normalization occurs exactly once, before immutable inputs are accepted; decoding never changes a hashed input.
- Leap-second constructor input and leap-second/submicrosecond persisted or wire record input are rejected, including deliberately recomputed matching digests. Altered deadline/digest still fails as before.
- No SQL/transport types move into the domain. No relaxed deadline/admission bound or automatic resubmission.
- Phase 03 must persist delivery_attempted_at before a transport write; revocation treats that no-receipt gap as uncertain. This is an implementation of the already gated no-false-stop invariant, distinct from deadline normalization. The marker cannot be cleared once recorded. No socket dispatch is implemented in p02.

## Focused proof after pass

1. Execute the real SQL operation round-trip regression and prove original digest and canonical deadline survive. Retain the pre-fix failure and final pass.
2. Typed tests distinguish constructor normalization from record validation: force .123456789, assert frozen .123456, forge a correct hash for the nonrepresentable record and ensure refusal. Also exercise a microsecond-aligned leap-second value at the constructor and a forged matching-digest leap-second record. The latter distinguishes representability validation from merely rejecting a bad hash. Rerun all cloudroom_ tests with nonzero inventory, plus existing auth-admission tests.
3. Fresh owned migrations, regenerated SQLx metadata, offline all-target compile/Clippy, format/whitespace. Existing p01 provider/UI evidence remains relevant to native SDK inputs; no additional provider inference is required for this precision correction.
4. Pin active notice CL-C002/r2 for affected p03/p04/p05/p07; later protocol tests must prove Node preserves the actual Rust wire hash, not merely a stand-in string order.

Gate approval permits only this precision correction; it does not accept p02 or waive final verification. User's Linux native-acceptance disposition remains unchanged.
