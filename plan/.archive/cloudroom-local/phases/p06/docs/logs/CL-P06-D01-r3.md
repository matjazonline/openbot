## 1. One physical-settlement definition

Move the existing exact OUTSTANDING_OPERATION_SQL semantics into an immutable SQL function taking command/outcome/observed native state. Protocol capacity, delivery/reconciliation, new retention and settlement trigger all call it; retain the Rust/SQL six-command/outcome/native-state matrix. An outcome is outstanding if NULL, or uncertain create/send without completed/failed/stopped native proof. Server wait expiry never proves physical stop.

Add server-owned settled_at, set once on the first transition to physically non-outstanding; unsettled rows have no settlement time. Trigger/check prevents forged early timestamp/classification drift. A terminal outcome before receipt may settle an untouched/refused effect; uncertain native work remains retained indefinitely until positive terminal proof. Add durable last_native_success_at to the machine from validated matching native completed effect evidence, separate from catalog/connection/authentication and preserved after old operations are removed.

## 2. Bounded server retention and workflow ownership

A local-agent maintenance port in application/local_agents drives bounded pages under supervised cancellation in the existing infrastructure supervisor (no detached loop). Each page uses DB time, transaction statement/lock limits, deterministic row locks/SKIP LOCKED and eligibility rechecks; no separate reclaimable lease is needed for a single atomic locked transaction. Cleanup never treats a read snapshot as deletion authority. Fixed90-day terminal-summary retention from settled_at,7-day settled/acknowledged observation detail retention.

Observation JSON may become NULL after7days while preserving sequence, operation, digest and accepted_at for dedup. Current-fence replay verifies the same digest and returns the original receipt even after detail compaction; changed content conflicts, stale fence rejects. Terminal output remains in operation summary for90days and as long as active/unresolved workflow references require it. Operation deletion cascades observation identity only after the90-day reconciliation window. Older missing replay fails recovery; never re-admits an old effect.

Standalone summary cleanup only deletes physically settled operations older90days with no call owner or active/prepared workflow session reference. Delete an unused session only after all operations and call/frozen-action session references are absent, and its own age/original-workflow eligibility is old enough. Catalog cleanup retains the current machine snapshot; obsolete snapshots and expired/consumed pairing/old revoked credential records may expire after their safe window. Installation-company identity remains a permanent small security binding.

Closed cross-tree references must not force unbounded multi-tree collection or permanent cycles. Add a narrow SQL-owned workflow_local_agent_retention_proofs record keyed to the exact shared local-agent dispatch identity (company/run/execution/invocation/digest/dispatch/kind), with physical settled_at. Its insert guard requires the current immutable call/operation link, a terminal run old enough for retention, and a physically settled operation older90days. It contains IDs/timestamps only, references the shared marker/run with lifecycle cascade, and never acts as a workflow receipt/result/approval/retry grant. No arbitrary proof insertion or mutable proof rewriting.

A bounded maintenance transaction may archive one or a page of terminal old calls into these proofs, then remove their call links and eligible native operations atomically under company→run→machine→operation/call ownership. Prepared calls of terminal old runs with no admitted native operation need no physical proof and may be removed only with terminal-owner checks; active prepared calls survive. This breaks reference cycles one closed owner at a time while preserving every active/prepared/unresolved edge. An operation remains while any extant call references it. General native summary cleanup then removes unreferenced physically old operations; session cleanup removes an old mapping only after all operations and extant call/frozen-action references are absent and the original workflow is terminal/old.

The existing atomic workflow tree-retirement owner remains responsible for run/job/action history deletion. Extend its eligibility to block while a session originally associated with the tree has recent/unsettled native operations or extant external call/frozen pending-action references. The shared unresolved-marker check may accept the exact guarded native retention proof solely for history retirement when cancellation/authority withdrawal prevented a normal receipt. This does not settle any workflow or create execution authority. Proofs cascade only with final run/action history deletion. After terminal call archival, frozen JSON is no longer an active/prepared reference; the reference check follows extant call+frozen-action ownership and accounts explicitly for guarded archived calls. All active pending actions keep their session reference.

Serialize non-FK frozen-action/session reference checks with admission/preparation by taking company FOR UPDATE SKIP LOCKED before native cleanup and strengthening existing workflow retirement's company lock similarly. Production admission/preparation takes current company authority locks. Preserve existing root/tree/execution/job order; machine/session/operation/call locks are deterministic NOWAIT/SKIP LOCKED, so contention rolls back/skips rather than waiting in reversed order. No collector reads another company's objects. Two old mutually referring terminal roots must eventually retire; a live/unresolved member must continue protecting its links. No unbounded connected-component traversal.

## 3. Explicit finite replay boundary for manual operations

After an operation row has expired, a caller must not be able to reuse its UUID as new work. New management start/control/catalog request IDs therefore require UUIDv7 with an encoded timestamp within24hours of authoritative database time and at most2minutes in the future. Saved exact replay is loaded and authorized before the freshness check, so an existing request keeps its frozen selection/deadline/result throughout retention. Never reinterpret a saved ID as a changed command. Browser forms generate server-side UUIDv7; JSON documentation names the requirement. Internal workflow invocation IDs and server bootstrap catalog IDs keep their existing current-execution/immutable-deadline authority. No compatibility decoder for UUIDv4 manual submissions.

Test old ID after summary deletion: it is stale and creates zero sessions/operations/effects. Also exercise exact saved replay beyond24hours, future timestamp refusal, and current IDs across actual HTTP/forms. Freshness is not authorization: company/original association and actor checks remain mandatory.

## 4. Plugin retention and backpressure

Add terminal-settlement/session-use times to the plugin-owned fresh SQLite schema. Compact bounded acknowledged terminal command snapshots only after at least90days; uncertain commands and unacknowledged output survive. A local idle timer cannot authorize session mapping deletion because pending server approval/queued work is invisible locally.

Mapping retirement uses a bounded, read-only current-connection protocol exchange, separate from immutable native-operation observations: plugin requests retirement eligibility for at most100 locally old mapping IDs plus a random request nonce; server responds with that nonce and only IDs permanently absent from the current company's machine/installation sessions. Both messages carry the current connection identity and are fenced before processing. One outstanding page, fixed timeout/backoff and normal frame/rate bounds; reconnect discards the page/nonce. Server eligibility is queried only from actual committed absence, never age alone. There is no new effect command, SDK capability or mapping-restoration/import authority.

Absence is safe retirement authority because session cleanup already protects all active/prepared/unresolved references, and a retired session ID cannot be newly admitted: manual session IDs equal expired UUIDv7 request IDs under section3; internal workflow session IDs require their exact durable invocation/run and cannot be recreated by a terminal/retired execution. New executions use new identities. No administrative caller may resurrect an old session via raw caller-supplied IDs. Preserve this invariant at every creation owner.

On a matching current-fence/nonce response, plugin SQLite atomically deletes only the unchanged candidate mapping with no pending command/outbox reference; keep all other mappings. The mapping's immutable thread/selection binding is checked against the locally captured page before deletion. No server acknowledgment of this metadata-only deletion is needed: lost query/response keeps the mapping, repeated requests see the same irrevocable absence, and successful local deletion leaves no new effect or unsent terminal fact. No cross-connection cached response may retire a mapping. Retirement absence is an installation-history guarantee, not a claim that database backups cannot restore deleted rows. Restoring Openbot SQL history behind a recorded retirement requires revoking/re-pairing affected installations (new identities, no old replay), unless the operator restores one coordinated SQL+Cloudroom profile+plugin-secret/journal snapshot from the same point with the old mapping intact. A SQL-only rollback must never reuse a newer plugin journal/mapping state merely because the observation cursor happens to match: mapping deletion does not advance that cursor. Document and test this restore boundary; no hidden mapping reconstruction from an arbitrary native thread. During disconnection mappings remain bounded/retained, with visible admission pressure if4096 slots fill; reconnect can reclaim genuinely retired mappings.

Require combined actual server-store/plugin journal+Dispatcher proof crossing90days: a prepared approval and a queued not-yet-seen server Send each keep their mapping despite local old age, then continue on the original selection/thread exactly once. After server ownership and retained summaries truly retire, the authenticated absence response permits local deletion. Forged/stale nonce/fence, other-installation scope, pending local commands and lost responses never delete usable mappings. p07 adds the real transport/inference acceptance; do not claim it from an isolated journal fixture.

At64MiB outbox/4096-history bounds, preserve all unacknowledged terminal output and reserved terminal headroom. Expose journal bytes/reservations/counts/admission-paused diagnostics through the existing plugin CLI; server diagnostics expose its own durable queue/age/permission/uncertainty/reconciliation and last native success. The two views do not pretend a socket or catalog proves provider login/inference. Capacity refusal must not kill reconciliation of existing commands: handle admission pressure within the owned worker, keep draining ACKs and observing admitted work, stop new effects visibly and bound retry timing. Old missing commands after the retention horizon cannot acquire fresh SDK authority; their immutable elapsed deadline/refused recovery path wins. No bound is raised.
