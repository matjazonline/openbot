## 1. One physical-settlement definition

Move the existing exact OUTSTANDING_OPERATION_SQL semantics into an immutable SQL function taking command/outcome/observed native state. Protocol capacity, delivery/reconciliation, new retention and settlement trigger all call it; retain the Rust/SQL six-command/outcome/native-state matrix. An outcome is outstanding if NULL, or uncertain create/send without completed/failed/stopped native proof. Server wait expiry never proves physical stop.

Add server-owned settled_at, set once on the first transition to physically non-outstanding; unsettled rows have no settlement time. Trigger/check prevents forged early timestamp/classification drift. A terminal outcome before receipt may settle an untouched/refused effect; uncertain native work remains retained indefinitely until positive terminal proof. Add durable last_native_success_at to the machine from validated matching native completed effect evidence, separate from catalog/connection/authentication and preserved after old operations are removed.

## 2. Bounded server retention and workflow ownership

A local-agent maintenance port in application/local_agents drives bounded pages under supervised cancellation in the existing infrastructure supervisor (no detached loop). Each page uses DB time, transaction statement/lock limits, deterministic row locks/SKIP LOCKED and eligibility rechecks; no separate reclaimable lease is needed for a single atomic locked transaction. Cleanup never treats a read snapshot as deletion authority. Fixed90-day terminal-summary retention from settled_at,7-day settled/acknowledged observation detail retention.

Observation JSON may become NULL after7days while preserving sequence, operation, digest and accepted_at for dedup. Current-fence replay verifies the same digest and returns the original receipt even after detail compaction; changed content conflicts, stale fence rejects. Terminal output remains in operation summary for90days and as long as active/unresolved workflow references require it. Operation deletion cascades observation identity only after the90-day reconciliation window. Older missing replay fails recovery; never re-admits an old effect.

Standalone summary cleanup only deletes physically settled operations older90days with no call owner or active/prepared workflow session reference. Delete an unused session only after all operations and call/frozen-action session references are absent, and its own age/original-workflow eligibility is old enough. Catalog cleanup retains the current machine snapshot; obsolete snapshots and expired/consumed pairing/old revoked credential records may expire after their safe window. Installation-company identity remains a permanent small security binding.

Workflow-owned calls/operations are reclaimed by the existing atomic workflow tree-retirement owner, rather than a competing deletion protocol. Extend its eligibility to block while a session originally associated with the tree has recent/unsettled native operations, or any external-tree call/frozen pending action references it. A tree's own local call must be terminal with native settlement older90days. Prepared calls for a terminal old run without admitted operation may retire with that run; active/prepared calls for other runs must survive.

The shared unresolved-marker guard may recognize exact immutable local-agent call+physically settled old native-operation proof solely for retention eligibility when cancellation/authority withdrawal prevented a normal workflow receipt. This never creates a receipt, workflow success, publication or retry authority. Native late audit can release physical retention only after matching proof and the90-day window.

Serialize the non-FK frozen-action/session reference check with admission/preparation by taking the company row FOR UPDATE SKIP LOCKED before native cleanup and strengthening existing workflow retirement's company lock similarly. Production admission/preparation already takes current company authority locks. Then keep existing root/tree/execution/job order, and take machine/session/operation/call locks deterministically with NOWAIT/SKIP LOCKED; contention rolls back/skips instead of waiting in a reversed lock order. Capture native call/operation IDs transaction-locally, delete the tree's local call links and eligible owned operations, remove eligible originally-owned sessions, then let existing run/job retirement commit all remaining cascades together. External calls/active owners block deletion. Every deletion is company-qualified.

## 3. Explicit finite replay boundary for manual operations

After an operation row has expired, a caller must not be able to reuse its UUID as new work. New management start/control/catalog request IDs therefore require UUIDv7 with an encoded timestamp within24hours of authoritative database time and at most2minutes in the future. Saved exact replay is loaded and authorized before the freshness check, so an existing request keeps its frozen selection/deadline/result throughout retention. Never reinterpret a saved ID as a changed command. Browser forms generate server-side UUIDv7; JSON documentation names the requirement. Internal workflow invocation IDs and server bootstrap catalog IDs keep their existing current-execution/immutable-deadline authority. No compatibility decoder for UUIDv4 manual submissions.

Test old ID after summary deletion: it is stale and creates zero sessions/operations/effects. Also exercise exact saved replay beyond24hours, future timestamp refusal, and current IDs across actual HTTP/forms. Freshness is not authorization: company/original association and actor checks remain mandatory.

## 4. Plugin retention and backpressure

Add terminal-settlement and session-use times to the plugin-owned fresh SQLite schema; compact bounded acknowledged terminal commands/mappings only after at least90days, with no pending outbox/native command or referenced mapping removed. Unknown/uncertain commands are nonterminal and never expire merely by wall time. Acknowledgment remains the existing contiguous cursor, and compaction runs under the existing process lock/service lifetime. No Cloudroom internal tables.

At64MiB outbox/4096-history bounds, preserve all unacknowledged terminal output and reserved terminal headroom. Expose journal bytes/reservations/counts/admission-paused diagnostics through the existing plugin CLI; server diagnostics expose its own durable queue/age/permission/uncertainty/reconciliation and last native success. The two views do not pretend a socket or catalog proves provider login/inference. Capacity refusal must not kill reconciliation of existing commands: handle admission pressure within the owned worker, keep draining ACKs and observing admitted work, stop new effects visibly and bound retry timing. Old missing commands after the retention horizon cannot acquire fresh SDK authority; their immutable elapsed deadline/refused recovery path wins. No bound is raised.
