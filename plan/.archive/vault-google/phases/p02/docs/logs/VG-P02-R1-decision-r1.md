### Proposed architecture VG-P02-D1 / r1 (NOT YET GATED)

1. New module-owned adapters/persistence/integrations directory, separate from existing channel installation persistence. A dedicated PostgresVault wraps the existing PgPool/cipher and implements application-private account/credential/lifecycle ports. Public VaultManagement implements ManagementGateway; LocalIntegrationGateway composes it with explicit Unavailable methods for later-phase connect/grant/execution. No silently successful defaults. Host routes and workflow/connection code never select integration_accounts or envelopes.
2. Init schema gains integration_accounts with owner namespace/subject/key unique, immutable account/provider/config/method/schema identity, bounded metadata/identity/envelope and positive account/auth/generation versions; status/envelope checks deny disconnected rows, reconnect_required may retain encrypted diagnostics. Provider canonical authorization key uniqueness is scoped by owner/provider/config (not Google's tuple globally). Code registry validates current adapter-owned schema and payload on every writer/read; malformed persisted JSON fails with sanitized errors. Metadata and credential projections are distinct; ordinary list/detail selects no envelope.
3. Persist a module-owned owner-state row, keyed by namespace/subject. Creation locks that row and counts+inserts in one transaction (128 cap); teardown retires it to prevent resurrection. No users/company FKs or joins. Account mutation locks the scoped row and verifies expected account revision before applying the one domain revision table. Static replacement rejects managed bundles or immutable identity/app substitution. Private registered-adapter writers alone create/replace managed credentials. Deletion disconnects/clears and deletes atomically; p02 cannot create bindings, grant-aware destructive semantics are completed in03.
4. Distinct integration_account AAD binds owner namespace, subject, account ID, provider, config, method and schema. Existing enc:v2/key handling retained. Context-specific 16KiB plaintext limit, existing global limits unchanged. Inventory/status/keyset/rotation/CAS implementations delegate all new account SQL to integrations persistence, preserving all logical revisions and generation on rewrap. Stale ciphertext CAS must lose to owner replacement or private credential writes. Full convergence and unavailable-key behavior use existing machinery.
5. A module lifecycle port records idempotent durable owner/host teardown intents before host deletion. Owner recording retires its owner-state and disconnects credentials in the same transaction so failed cleanup cannot preserve usable accounts. Local host adapters call explicit narrow hooks inside deletion transactions; user deletion also records owned-company teardown intents. Host state remains authoritative for dispatch. A bounded local teardown drain runs through the host's existing supervised WorkflowEngine worker group, with cancellation reaching the database future; no detached tasks, token refresh loop, service, or cross-module account joins. Cleanup is idempotent and transactional; crash rolls back incomplete work and restart retries the retained intent. Company cleanup cannot remove unrelated private accounts; p02 has no grants/attachments, and future03 must extend this port with grant invalidation. No database cascade is relied upon to implement module cleanup or future remote lifecycle.
6. Trusted owner adapter maps verified session user UUID into a code-configured stable Openbot client namespace/subject shared with lifecycle hooks. Add authenticated /ui/profile/vault GET/POST and /{entry_id} PUT/DELETE (plus owner disconnect if useful), using gateway ports, existing session/origin/body-limit conventions. Profile links to a small Vault page. Secret inputs always blank, replacement only; metadata/status only in responses, sanitized form errors, positive expected revisions, foreign IDs hide existence/labels. UI explicitly says server-encrypted and company attachment is unavailable until03. Use existing progress indicators and theme tokens, escape all untrusted text/attributes; regenerate CSS if needed.

Failure/transaction boundaries: fixed redacted IntegrationError variants (including typed Conflict), no raw SQL/provider/JSON error text or write structs in tracing. Expected revision prevents stale management writes during private writes. Owner lock covers cap competitors and retirement races. Cipher AAD prevents row/context substitution. Inventory rewrap CAS touches envelope only.
