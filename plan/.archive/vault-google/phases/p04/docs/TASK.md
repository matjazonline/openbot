## D1/r2 — bounded reusable OAuth lifecycle

Share one configured vault/registry between gateway and binding authority; no credential copy in host tables. Login scopes/routes/storage stay unchanged.

Crashed processing expires; no code retry/revival. Frozen reconnect target is nonauthorizing metadata, deliberately not a deletion-blocking FK; final completion must find that exact existing current account, never treat missing reconnect as new. Short-lived HS256 state uses existing JWT_SECRET signing primitives with a distinct issuer/audience/purpose integration-connect/v1, attempt, verified owner, app/config/provider/policy, nonce, browser-session binding, safe return and reconnect identity/version. Build/validate URL before persisting an attempt, avoiding an unreachable active attempt on URL rejection.

Module finalizer locks owner state, intended reconnect account, then attempt; rechecks status/expiry/registeredpolicy and expectedAUTHrevision. Pure registered provider finalization validates/merges its candidate against only that locked previous payload. No provider network under these locks. Host supplies its verified session valid-until as required temporal facts to the module finalizer. Under all module locks, immediately before the atomic account/attempt transition, finalizer requires current database time before that session bound, attempt expiry and caller deadline; cap lock waits by these bounds. Session row locks preserve revocation/security facts but cannot freeze expiry. Module atomically writes account and connected attempt outcome at that authorization point; host releases locks. Service requires actual finalizer execution and returns the durable owner-scoped attempt projection, so a skipped/forged host return cannot manufacture success. A callback-skip guard prevents successful completion without invoking the finalizer. Initial admission alone is insufficient after provider waits.
