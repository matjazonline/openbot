## Architecture JEV-P02-D1/r1 (awaiting independent review)

1. New company_typesafe_connections table keyed (company_id,id), enabled, monotonically incrementing revision, bounded explicit model allowlist, and encrypted bearer envelope. Separate from agent model connections. Context is new typesafe scope + immutable company/id; add this table to credential inventory/KEK rotation. No legacy decoder, no origin input. CRUD management port returns only public ID/enabled/revision/model/readiness projections, takes SecretString on create/rotation, requires owner/admin within company-first transaction. Updates/rotation CAS expected revision and same ID; no automatic replacement.
2. Existing publication bundles already freeze literal model/questions with compiled const schemas. Publication has resource slots, not selected IDs: verify every Jev model has at least one enabled ready same-company connection at publication. Binding selects exactly one ID per slot and verifies *that ID* permits every model used on the slot. Admission and binding activation repeat checks under company authority locks. ResourceStatus supported_contracts carries allowed exact model IDs for typesafe, without secrets. Do not freeze a connection revision or credential into publication/run; secret rotation affects next use.
3. Current execution authorization helper is bounded by persisted run/execution, reads actor and immutable bundle/resources, locks current authority before workflow-local rows, validates selected typesafe slot and exact literal model/questions, then checks enabled/current model/current envelope. Provider use in p03 must call this at reservation/credential resolution and fence the execution; p02 adds reusable helpers and tests, never a production handler. Disabled/missing/model-removed authority fails terminally; there is no connection search/replacement at runtime. Linearization is the authorization transaction; later revocations affect later authorizations. Competing claimant/revoker tests demonstrate lock order/recheck.
4. Fixed upstream endpoint https://api.typesafe.ai/v1/systemone belongs in eventual HTTP adapter p03; management/persistence accept no origin at all. Only p03 adapter test constructor may allow loopback. Upstream rechecked 2026-10-28: System One bearer authorization; models page requires exact version pin because aliases move. https://docs.typesafe.ai/api/system-one and https://docs.typesafe.ai/models.
