## Architecture JEV-P04-D1/r1 — pending gate

- Source with.assets is an optional literal map, maximum four logical identifier names, values strictly {channel_id, thread_id, sha256}. UUIDs identify existing private message attachments; sha256 is a mandatory lowercase 64-hex expected content digest. No URL, storage key, inline bytes or unverified mutable reference is accepted. Source/compiled bundle/run views/sample reports retain only this inert metadata.
- Application-owned JevAssets read/current-authority port composes a persistence metadata authorization port with private storage. Persistence checks persisted run actor/company, current company membership and channel/thread view permission, attachment membership of that exact company/thread, current live execution fence and frozen inputs. Authorize before storage access and again after any queue/read and before provider use. Unauthorized/missing fails terminally without provider invocation; infrastructure failures remain retryable.
- Each object read enforces 24 KiB before/during streamed allocation with a 5-second bound. Validate metadata MIME, actual PNG/JPEG format and full decoding, no animated PNG, dimensions 280..1024 each and <=1,048,576 pixels. SHA256 must equal source and stored attachment metadata; changed objects fail before replay/provider. Request remains <=64 KiB including base64. Reuse already locked image crate version with only PNG/JPEG features. Existing unbounded storage read remains outside this path; add required explicit bounded read implementation to storage adapter and fake.
- Provider state for image requests is {content: original_state, assets: {logical_name: opaque_placeholder}}. Box instructions must explicitly name a declared `assets.NAME` path in backticks; all images appear once in assets state, text questions can refer to content/assets. No replacements of user strings. Placeholders are server-generated deterministic SHA256 tokens of the canonical metadata request plus asset name; reject accidental occurrence in original request. Text-only requests retain existing wire shape.

Box tagged union contains instructions only, criteria forbidden. Exact output coordinates/confidence [0,1], strict left<right/top<bottom, static mixed output schema.
- Prepared request separates inert canonical identity from ephemeral wire bytes. Persist identity (includes expected content digests) and SHA256 of exact hydrated wire bytes, never base64. Preserve metadata equality against frozen input at admission; retries hydrate and verify identical bytes/digest. Settlement receives the same prepared request to verify exact wire digest under fence. Only ready hydrated image requests may enter provider/admission; token reservation includes wire bytes plus a conservative per-image decoded pixel allowance because upstream has no image-token estimate.
