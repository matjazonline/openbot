# 03PA-P04 D1/r3 — Correct the native source proof obligation

No backward compatibility. D1/r1 and D1/r2 remain immutable historical decisions; this revision
changes only the unsupported role-origin native proof assumption below. Broker identity,
authorization, historical recovery, actor prefixes and all existing guards remain unchanged.

## Contradicted assumption and concrete trace

B1-R1/F1 correctly observes that the role-selector test exercises a helper, not native ingress.
However, an agent-origin native local operation cannot be produced by the current system:

- `application/workflow/actions/local_agents.rs:21–39` explicitly rejects every local action whose
  `request.context.origin != ToolCallOrigin::Workflow`, in `FrozenAction::local_agent`.
- Exhaustive `FrozenAction::local_agent` references show one initial producer, persistence
  `workflow/local_agents/preparation.rs:5–67`; other references only restore/revalidate it.
  Its context comes from `workflow/http_runtime.rs:62–78`, which sets Workflow unconditionally.
- `local_agents/admission.rs:22` is the sole caller of that producer and admits only a real
  local_agent.run execution. The worker port accepts ClaimedWorkflow/LocalRunInputs, not an
  agent-tool origin. `AgentBuiltinTool` and `AgentActionTools::dispatch` expose no direct local-run
  agent tool. An agent may call a workflow tool that starts a child containing local_agent.run;
  the child native action still has Workflow origin and retains normal child-run ownership.
- Native source authorization invokes `local_agents/delivery.rs` and revalidates the frozen local
  action through `lock_current_with_locks`, which calls the same rejecting constructor. Thus a
  forged SQL Agent-origin local action would fail before becoming valid current native authority.
- `agent_origin.rs:21–42,93–110` is a generic shared authority/selector path. Its Agent arm supports
  ordinary agent actions, but the local-action constructor excludes that arm in native ownership.

The original D1 §4 wording assumed that conditional generic arm had a current native producer.
Creating the F1 fixture as worded would require enabling a new agent tool/origin or bypassing the
existing constructor. Neither is a requirement of Plan03. Do not introduce that feature or bypass.

## Revised invariant and verification mapping

1. Native local actions and private MCP broker actions retain Workflow origin. Preserve the strict
   constructor/provenance rejection of Agent-origin substitutions. Add a discriminating guard test
   using a genuinely prepared local action if existing tests do not already cover that rejection.
2. Preserve sealed-role support and the RowLocks parameter in the shared selector. Retain the
   helper-level contention test as exactly that: it proves captured manifest/role/revision locks,
   identity selection and internal DatabaseTimeout. It is not native boundary/rollback evidence.
   Ordinary role admission/runtime regressions and the final full suite remain mandatory.
3. For actual native Workflow-origin continuation, exercise the real pre-body authorization,
   native MCP admission and live/preparation boundaries with competing actor/requester account
   locks and actual source/selected-native-owner locks. Use real admitted operations and native
   observations. The requester must be resolved by existing production `provisioning::requester_on`
   from a genuine admission/root/message context; include distinct actor/requester when present.
4. Assert bounded ServiceUnavailable for contention, unchanged call/run/dispatch state after the
   failed attempt, release the competitor and retry successfully, retaining exact original native
   harness agent/revision and immutable source association. Existing principal/thread/parent/grant/
   machine and identity tests may be reused when their exercised path and assertions match.
5. This is a correction to the proof obligation, not a waiver of an exercised current branch.
   Complete F1 only after independent acceptance of this revision and its real-boundary proof.
   F2 is an independent wording correction to direct workflow help, retaining the keyed-model rule.
