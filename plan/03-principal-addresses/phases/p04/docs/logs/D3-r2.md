## Problem and ownership boundary

A group/chain/hook can be applied before its creator returns nonzero or times out. Current
post-success flags then omit it from cleanup. Timers do not prove an unsuccessful call had no
side effect. Existing signal proof covered successful return only.

Both supported wrapper entrypoints exec the helper as its own Bash process. Resource names already
include that live kernel PID plus a random nonce. Current cooperating helpers therefore use distinct
private namespaces even before the objects exist; stale/existing collisions must be rejected before
claim. This remains a normal-test guard, not protection from a privileged actor deliberately forging
another live helper's private names (D3/r1's existing non-hostile privilege boundary). The opaque
prefix alone never authorizes deleting a preexisting object. No broader prefix cleanup is allowed.

## Decision

1. Check initial absence before claiming each group/chain identity. Group lookup uses bounded native
   getent: status0 means existing/collision and aborts untouched; documented status2 means absent;
   every other failure aborts without claim. Chain lookup uses a successful bounded full filter-table
   `iptables -S` listing and an exact complete `-N <private-name>` line. Do not interpret an arbitrary
   failed `-S <name>` as absence. Both IPv4/IPv6 identities are checked.
2. After validated absence, record ownership INTENT before launching groupadd or chain creation.
   Keep the deferred INT/TERM handling through that publication. If the native mutation returns
   nonzero/timeout, cleanup still owns this exact newly claimed private identity. Do not retry setup
   and do not run the target command. Preserve the original nonzero or130/143status.
3. Record the exact OUTPUT jump intent before insertion. Its target chain is already ours and was
   absent before acquisition; no preexisting jump could target that absent private chain. Only the
   exact `(firewall,OUTPUT,GID,private-chain)` tuple may be removed.
4. Cleanup reconciles intended resources rather than assuming return status established existence.
   Check the exact jump; remove if present. A failed/unknown probe is a visible incomplete-cleanup
   result. A missing jump needs no deletion; subsequent owned-chain deletion also refuses a still
   referenced chain, preventing a false successful cleanup. Inspect chains through a successful full
   native listing; flush/delete only intended identities actually present. A failed listing is an
   error, never an empty state. Continue bounded cleanup of other owned identities.
5. For the claimed group, bounded groupdel is authorized even if acquisition acknowledgement was
   lost. Documented groupdel status6 means already absent, not failed removal. All other failures,
   including timeout, remain visible. If firewall cleanup failed, retain the group as before so its
   GID cannot be reused under a stale hook. Do not report incomplete removal as success. No foreign
   group or chain is enrolled merely because its acquisition returned nonzero.

The private-name absence checks and live-PID namespace are the acquisition authority; intent lists
are cleanup authority; bounded native reads/deletes establish actual completion. No filesystem
recovery records or new persistent service are needed. Existing resources at a generated identity
are left untouched and cause a controlled refusal. Callers do not source the helper as a library.

## Required discriminating proof

- Both entrypoints: execute real groupadd, real chain creation, and real OUTPUT insertion, then force
  nonzero return and setup timeout before the caller can receive successful acknowledgement. Verify
  no target command, meaningful original status, and no remaining owned objects after successful
  cleanup. A timeout case must hold after the actual mutation, not fail before it. Keep all failed
  evidence and teardown exact fixture-owned objects if a counterexample fails.
- Preexisting group and chain collisions survive unchanged; own earlier resources are cleaned when
  a later acquisition refuses. A failed absence probe must never authorize ownership/deletion.
- Preserve concurrent-wrapper distinct scopes and supervisor traffic, original UID/groups/env/args,
  actual creator INT/TERM windows, actual privileged cleanup child death/no late effect, and bounded
  visible cleanup failure. Existing real Linux regression remains in CI.
- Confirm the old post-success-only setup loses resources under the new after-mutation fixture, or
  retain an equivalent discriminating counterfactual. Test assertions must inspect real OS state.
- Recheck final source/evidence independently, then complete remaining current CI/private gates.
  Rust/migrations/Cargo/Darwin projection is unchanged; existing successful full native checks may
  be reused only within that byte-identical scope. No whole-local-green claim until the missing
  Playwright prerequisite is installed and the affected JS gate is rerun successfully.
