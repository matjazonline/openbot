## Evidence and problem

The general CI job on exact957de863 lost hosted-runner communication while the isolated
DB suite ran; annotation retained in R7-ci-verify-annotations.json. Prior candidates lost
communication too. Debug metadata removal did not prevent this latest loss. No OOM claim.

scripts/test-network-isolation.sh installs OUTPUT owner rules against id -u, which is the
same account executing the CI agent and test command. services/memory/scripts/test-network-isolation.sh
has the same selection. These rules therefore also deny control-plane sockets owned by that
account. A long-running test command outlasts the runner reconnect/heartbeat tolerance.
This is a substantiated scope defect from owner-match semantics; exact attribution of every
past runner loss remains unproved pending a discriminating Linux check/current full CI.

## Decision

Use an ephemeral dedicated primary group for the wrapped command and children on Linux,
while retaining the invoking user ID and ordinary supplementary groups. Standard Linux
setpriv sets the command UID back to the caller and its primary GID to the temporary group;
iptables/ip6tables owner --gid-owner selects only sockets opened by that command tree.
The caller/runner keeps its original group and its network access. This preserves existing
checkout/cache permissions through the original user ID and avoids another writable-home
or build-cache design. Allocate the group with groupadd using a collision-safe unique name,
resolve its numeric ID, and remove it in the same bounded wrapper cleanup that removes the
exact firewall chains. Fail closed if any required setup or guarded preflight fails.

Keep loopback IPv4/IPv6 and existing original-destination PostgreSQL5432 allowances, final
REJECT rules, proxy removal and Cargo offline mode. Run the existing loopback/egress preflight
and actual command under the SAME temporary group. Preserve command arguments, exported
fixture environment, HOME/PATH, exit status, and existing INT/TERM cleanup behavior. Do not
add endpoint exemptions, allow arbitrary public addresses or remove isolation.

Apply the same protocol to the standalone memory service wrapper. Prefer one coherent
implementation of the Linux mechanism with both entrypoints delegating where the memory
service standalone image/context permits; otherwise keep the small platform-specific code
explicitly equivalent and test both entrypoints. Darwin sandbox behavior stays identical.
No production runtime/schema/permission contracts or resource/time limits change.

## Required proof

- A discriminating Linux regression starts a real local TCP fixture on a non-loopback address.
  An unguarded supervisor connects before and while the wrapper is active; the guarded child
  cannot connect there, yet can use loopback. Child and nested descendants share the dedicated
  group; original UID, environment, arguments and command status are preserved. Check cleanup
  on command failure and after guarded setup failure. The old UID-selected wrapper must fail
  the control-plane preservation assertion. Exercise both entrypoints, not a syntax stand-in.
- Keep the existing IPv4/IPv6 egress preflight, compile/migrations/database, stock-stack and
  lease gates unchanged. Run required current-candidate CI to establish real runner survival.
- Locally on macOS: shell syntax and Darwin preflight/targeted command; Linux behavior is
  unavailable until the exact candidate runs under CI. Do not call local syntax a Linux PASS.
- Source/material change requires new snapshot/evidence, affected independent B review and
  final acceptance. Prior source/focused proof remains historical for88d4 only.

## Failure behavior and ownership

Setup errors must not execute an unguarded command. Cleanup must handle partially-created
chains/group safely using exact owned identities and must not target another invocation.
Concurrent invocations have different groups/chains; one cleanup cannot alter the other.
The original caller already has CI sudo capability; this is a test isolation boundary for
normal test command sockets, not a privileged-hostile-process security sandbox.
