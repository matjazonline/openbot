# 03PA-P04 D1/r4 — Native action entry owns the original account prefix

No backward compatibility. No new producer, schema, authorization policy or timeout increase.
D1/r1–r3 remain historical. This revision specifies the shared entry implementation needed to
fulfill their existing account-order/NOWAIT contract after real boundary proof contradicted it.

## Evidence and scope

R2/F1: mcp_step_request calls http_runtime::facts, which prelocks the broker actor with Wait and
locks company/run before native_mcp::live_on discovers the original Workflow requester. The exact
binary test fails in live() at mcp_step_request; PostgreSQL records a transactionid wait on
SELECT id FROM users WHERE id=ANY($1) ORDER BY id FOR SHARE. Logs orca-f1-exact-diagnostic1.txt
and orca-f1-exact-waits1.json. Native ingress passes; this is the broker action's outer entry.
Equivalent affected entries: actions::prepare (fresh intents), mcp_use, action_dispatch account
prelock→McpActionAuthority and integration_authority::HostDispatchAuthority::current.

## Decision: extend the existing sorted account owner

1. action_authority/account_hints remains the one owner of purpose-specific sorted account unions.
   For a current native broker effect it also includes the REAL original local operation's actor
   and requester. Observe native_mcp_calls/local_agent_operations via the run's immutable native
   call marker and tenant/run identity. For Workflow origin use the existing parked_subject_on
   mapping to the source ActionScope and existing actor_hints_on/requester_on; Direct origin needs
   only its saved actor. Validate source actor equals broker/call actor. Do not infer requester
   from the broker's synthetic trigger or from unrelated membership, and never fabricate IDs.
2. Combine original source accounts with broker actor/requester/reviewer and existing purpose-specific
   approval/escalation/recipient accounts BEFORE locking any of them. Lock the deduplicated sorted
   union with NoWait, then company authority with NoWait. This preserves arbitrary integration
   credential owner/reviewer accounts in the same union; a separate early source helper that takes
   company before those accounts is rejected. Re-read native lineage and hints after ownership;
   changed/missing source refuses, never locks a newly discovered account late. Later live_on still
   proves current frozen operation/source/association/bundle/machine/grants and lifetime identity.
3. Select native NoWait at outer callers, including their run ownership, before a generic Wait
   helper can block. Carry or derive the native mode through existing shared facts/account/run
   helpers; reuse RowLocks rather than add a parallel authorization protocol. Native busy errors
   become ServiceUnavailable at the existing public/service boundary; rollback releases the whole
   transaction before retry. Ordinary effects retain Wait and existing authorization semantics.
4. Native classification is based on the stored run/call identity, never caller-supplied flags or
   ToolCallOrigin (native actions intentionally have Workflow origin). Structural historical proof
   remains provenance::restore_on and never gains current authority from a newly looked-up person.

## Historical and consumer dispositions

- actions::prepare keeps its read-existing-intent branch and immutable replay contract; a replay
  does not run a new current-source prefix. Fresh intent authorization does. The existing recorded
  dispatch/receipt paths retain their observation semantics and do not acquire original-source
  requester accounts or require a surviving parked source. Existing recorded/retired markers must
  explicitly select observation before current native lineage lookup. Missing live lineage is
  refused for fresh effects; it is not reclassified as an ordinary effect.
- mcp_step_request/shared facts uses the corrected prefix and native run mode before preparing an
  ActionRequest. Normal HTTP/tool callers keep their established policy.
- mcp_use native branch establishes the same prefix before its first company/run authorization;
  ordinary branch preserves current semantics. Later live_on remains required.
- Dispatch and integration final guard use the same account-hints owner (including their reviewer/
  credential owner), before company/fence/run/resource validation. Native load_on run locking uses
  NoWait. Existing job/attempt/fence ownership/lease/commit mechanics are unchanged; this change
  owns added source authority and account/company/run acquisition, not a new worker-claim protocol.
- Existing role-selector helper, original-principal/thread/parent/grant/machine/native-revision
  guards and all authoritative after-lock validation remain. No generic origin branch is enabled.
- Retain caller inventory and explicitly account for historical wrappers/checkpoints/receipts;
  shared prefix changes must not turn observation/recovery into a fresh source-authority check.

## Failure and verification contract

Missing/wrong-company/mismatched source or actor refuses; a busy required account/company/run or
source owner returns bounded native ServiceUnavailable; no call/run/intent/dispatch/effect writes
survive. Account/lineage changes across the prefix refuse and cannot cause a late account lock.
Release competitor then retry keeps exact original native harness agent/revision and association.

Focused assertions retain both saved F1 tests, and expand the same real production fixture to cover
fresh ActionService prepare, mcp_use and actual dispatch/final integration guard where admitted,
with competing actor and distinct requester; include source revision and native run contention in
relevant outer preparation cases. Assert unchanged effect state and successful retry, not helper
success alone. Existing immutable-intent replay/recorded dispatch/unknown recovery after original
actor or principal deletion must still pass without live-source dependencies. Run native_mcp_,
affected ordinary MCP/action/approval/receipt/integration/requester suites and source reachability.
Regenerate SQLx metadata against fresh owned schema even for runtime queries. Final scripts/check.sh
and missing CI gates remain required; no timeout/limit/assertion relaxation. B reviews the whole
correction delta/consumer dispositions and actual evidence before final acceptance/main publication.

The only extra queries/surface allowed are the native-lineage/mode reads and internal shared helper
results needed by this existing protocol; no service, dependency, configuration or persisted field.
