library copy, onboarding and the Agent Builder. Under its existing actor account→company lock,
insert the agent/principal, register exactly `agent.slug` in `addresses`, apply direct settings,

`AddressTarget::Principal(principal)`. Place in department/role last, preserving sorted desk gates.
After inserting the address, explicitly call the existing `integration::email_binding::sync_principal_email_binding_on` on this transaction. That helper reads the registered slug and calls `write_canonical_email_binding`, owning insertion/update and binding audit. Existing native address triggers only guard kind, advance settings revision and retire addresses; they do not provision transport bindings.
Any collision, missing keyed model, publication or placement failure rolls back every resource.
There is no automatic channel, `agent:{id}` command row, alternate address or forwarding path.
Library definitions alone remain unaddressed and unbound.

Refactor responsible native provisioning code into workflow composition/publication and typed
binding/selection, used by principal and shared-desk provisioning. Shared desks keep their ordinary
reply settings and department provisioning. Avoid duplicate publishers or principal-only workflow
engines. `CreatedAgent` returns the agent and its typed principal id; internal creation may also
return typed workflow/version/binding identities. No desk id is synthesized for API/onboarding.

Agent slug and principal address stay equal. Add native deferred equality guards on agent/address mutations: an agent address cannot disagree with the same-tenant agent slug at commit. A lone raw agent/address rename that leaves them inconsistent is refused; this is a new guard, not an existing automatic writer. Keep the low-level fixture distinction explicit: the guard validates an agent address when present; production's one creation primitive guarantees its existence and published binding.

The production rename transaction owns the full write: existing authorized account/company→agent prefix, lock the agent principal, apply direct settings, update the agent and its existing address, then call `sync_principal_email_binding_on` before commit. Creation similarly holds/creates the principal before address and transport binding, then publishes/binds and places last. Never acquire the binding before its principal gate. The helper preserves the same lifetime binding id/namespace and updates the canonical endpoint plus audit; a taken address/endpoint or later failure rolls back agent, address, revision, binding and audit together. A rename does not retarget historical threads. Reuse p02's actual helper rather than add a second SQL/Rust binding producer.

Canonical endpoint keys are scoped local parts, not full mailboxes. `channel_bindings.external_endpoint_key` stays opaque/local; do not feed it directly to `qualified_email_identity`. Extend the existing transport renderer with application-address rendering from typed company/address slugs. The existing notification projection supplies the current optional route address reference (typed company/principal slugs); the worker renders a real recipient identity alongside its already minted notice Message-ID and passes that runtime value into projection commit. The commit revalidates the current expected projection and exact route before using it as DTO addressing, without treating that identity as authorization. Missing route remains the existing recipient failure, not a synthetic address. No application/persistence literal domain or `.invalid` mailbox, protocol-key parsing, new credential or per-agent transport configuration.

Production creation/rename tests assert the actual active lifetime email binding, coherent endpoint and audit, stable binding id across rename, collision rollback and both-order rename/ingress fencing. Raw SQL tests assert the equality guards. Replace noncanonical agent-address fixtures with production-created agents or canonical explicit native fixtures.

## 2. Persistent ownership and safe unused deletion

Add nullable `workflow_definitions.owner_agent_id`, with a tenant-scoped FK to
`agents(company_id,id) ON DELETE CASCADE`, and a unique non-null owner per company. This records
ownership of the one automatically provisioned direct workflow, independently of its current
selected binding. Explicit shared-desk workflows remain unowned. Record ownership in the original
creation transaction; user draft updates cannot assign/reassign it. Native immutability prevents
changing that identity after creation. Do not infer ownership from title, selected binding,
UUID shape, slug, or old provisioning command JSON.

Keep existing company→agent deletion locks and current authorization. Before retirement, refuse
if the principal has any direct thread or any retained run; no cleanup commits on refusal.
Remove the principal's workflow bindings/reply selection in the same transaction. Deleting the
agent then deletes its owned definition and own agent revisions by native cascade, whose existing
immutable-row guards allow parent teardown. Change only the agent_revisions→agent delete action
to cascade; retain every incoming revision/version/run/history/manifest/capability FK and guard.
External bindings to the owned workflow, retained runs, history or publications that reference an
agent revision/version therefore abort the whole delete. Do not delete external references or
broaden cascade actions on their FKs to make deletion succeed.

An unowned/shared definition is never deleted by this operation. Agent namespace retirement,
principal demotion, address endpoint retirement and follow-reviewer refresh remain transactional
and keep their current account/company order. The principal's archived identity is not live
authority; no physical principal deletion or historical ownership transfer is required. Raw parent
delete must retain reference constraints, and application tests assert rollback of all resources
when a retained reference refuses. Map real native conflicts to actionable delete errors.

## 4. Relay sender authority belongs to the authenticated producer

Keep a typed source `AddressTarget` and add explicit authenticated sending-principal provenance;
never derive an agent's authority from its owner's account or an inbound From string. Reuse
trusted `AgentToolOrigin` for tool-produced messages, and the exact terminal
`channel_reply_proposals.execution_id`/agent-history exchange for actual agent final replies.
A direct agent binding may speak as its own target principal even for a pure workflow final.
A pure desk workflow does not acquire an arbitrary agent identity from its bundle or department.

Carry the proven agent principal through `MessageRoutes`/planned canonical author and frozen
publication. Persist it as the canonical message author using existing `MessageAuthorWrite`
variants. Validate it against the actual same-tenant frozen agent tool origin, terminal agent
execution, or direct-target binding when writing; native deferred checks independently refuse a
forged agent author on a workflow message. Ordinary non-agent workflow messages remain system
authored. The canonical author persists after producer-run retention, so no new sender registry
or live-run pointer is needed for later relay.

`authorize_relay` reads the exact stored delivery/part through a purpose-specific application
port before resolving recipients. It verifies company, frozen source target/From, Message-ID,
recipient and content against the proof. From must be the source desk authorized by that run's
binding or the actual sending agent's own current principal address; never another agent's
address. The sending agent principal must still be live in that company. Return the authenticated
principal context, using Member-equivalent team status plus its own grants; do not substitute a
person principal. A non-agent system sender has no invented team/member/grant authority.

Rename `IngressOrigin::InternalChannel` to `Internal`, carrying source target, optional proven
agent principal and exact delivery proof. Use that principal for attribution and participation
on the receiving side. Remove internal desk ACL bypass: ordinary `participant_access` decides,
including derived department grants. An agent member of a members-only department desk succeeds;
an unrelated agent fails. Agent→private-agent mail is team traffic; personal targets keep the
person/owner policy. Non-agent system mail does not borrow an agent's grants. Desk email sender
syntax is still permitted for its authorized binding, without impersonating the desk's owner.

Extend `message_internal_relays` from required source_channel_id to exact-one source channel/
principal columns, plus authenticated sender when present. Its native guard proves exact
delivery/part/canonical author/From/recipient/content and current principal/target eligibility;
redelivery checks the complete proof shape. Guard before durable recipient effects and recheck
inside receiving commit with current source/target policy and ordered locks. A malformed,
foreign, retired or revoked source refuses atomically with no message/intent residue. The
identity-key-before-principal lock prefix remains; acquire source/target principal rows in one
sorted set. Source/target binding updates and account edits must not invert this order.

Hop count/bounded typed trace stay p02's contract. A principal and desk sharing a UUID are
different hops; a repeated exact typed target is a cycle. Keep context suffixes, whole-message
unknown-address privacy, spam/authentication and public-desk/private-agent independence.
Preserve authenticated notification origin inheritance through the proved delivery part and
sealed source message even after producer-run retention; never copy origin from subject/header.

## 6. Authenticated private-notice participation (R1/F2 correction)

Ordinary `principal_direct_can_participate` remains unchanged. A private system notice is not a team actor, even though it is a valid platform producer. Its exact purpose-specific authority is explicit at both storage and asynchronous admission:

### 6.1 Claimed projector to canonical direct commit

Replace the generic private platform-writer entry point with a purpose-specific agent-notice entry point, taking a crate-private authority record containing the exact notification event/execution/worker lease fence, notice id and expected principal/transport binding/workflow binding/configuration/settings revisions. The existing notification projector creates this record only after the hint→principal/accounts/company→source/event locks and complete current projection revalidation. No HTTP, external transport, ordinary application, or ordinary internal relay path can choose this authority branch. The wire/DTO author identity does not authenticate it.

Before provider keys, thread resolution or canonical writes, the principal gate validates that authority against native rows under the held locks: the exact event is still processing under the live execution/worker fence; it names this active agent notice/source/principal; the original case/source remains eligible; its current intended route, run-as account/current content authority and all expected binding/configuration/settings/transport identities still match. The candidate is exactly one To/mentioned application-origin notice intent and association at that principal, with no replied message, no attachment/outbound delivery, in-app-only policy, and its notice-derived transport Message-ID. Only this fully proven request bypasses the ordinary participant test. A typed Platform/Application/System label alone never does. A missing/changed proof returns the existing stale/lease/route outcome with whole-transaction rollback.

The canonical author stays the real company system principal, audience internal_only, with no fabricated person/agent identity or observed account authority. The native receipt guard and deferred completeness checks independently bind that exact private message/intent/notice/event/principal/binding/revision and key; no bypassed request can commit without its matching authenticated receipt and normal fenced event completion. Lease loss at final completion rolls back the entire canonical effect. Retain prefix/order/NOWAIT semantics from §5; no locks survive the separate queue backoff.

### 6.2 Sealed notice to exact targeted admission

At `admission_source::message`, after exact tenant/target/thread/message membership load, allow either ordinary direct participation OR an exact authenticated notice branch. The notice branch requires a non-null current admission claim on that message intent, proves its live execution/worker/generation fence, and matches all message/intent/principal/agent/binding/configuration fields through the immutable receipt and notice-target seal. It also checks the source/notice is still active, the intended route/actor/current content authority remains eligible and the captured binding/revision is still selected. Reuse existing native notice-source-live/route-match/eligibility predicates, consolidated in one purpose-specific predicate shared with native admission/handling-root guards. This is not a public flag on the source DTO.

Keep existing `claim_holds`, current binding checks, replay/source reauthorization, origin adoption, atomic run/job/handling-root creation and final claim settlement. The exception cannot enable a manual/message-trigger start without the exact targeted claim, another binding at the same principal, another revision, another message, or a withdrawn/stale notice. A native direct run insert must still satisfy the same exact authenticated targeted source/handling-root constraints. Missing proof never falls back to a random binding or an ordinary system participant. An already retired source follows existing targeted source-retired/failure semantics; it does not create a new case.

### 6.3 Required discriminating proof

Exercise the actual projector on a production-created default-private agent, then its real message-intent/admission worker: assert one system-authored internal_only direct message and intent at the actual principal binding, exactly one accountable handling root with its captured binding/revision/origin, and no outbound delivery. Message/receipt existence alone does not satisfy this criterion.

Add application and native negatives for ordinary system/application/internal-relay traffic, claimed origin/header only, absent or foreign event/receipt/claim, mismatched principal/message/intent/binding/revision, expired/lost fence, withdrawn or retired source. Deterministic barriers revoke the source/route both before canonical commit and before actual admission; assert zero unauthorized effect and original-case handling failure/terminal state as applicable. Include competing projectors/admissions and both-order lock/race cases from §5. Authenticated ordinary-agent ingress separately uses its proven canonical principal for direct policy and later admission; the observed wire From never substitutes for that principal.
