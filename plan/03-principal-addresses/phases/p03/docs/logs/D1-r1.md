# 03PA-P03 D1/r1 — Production principal provisioning and authenticated relay

> No backward compatibility. Edit init schema and reset owned disposable databases.

Original criteria and contract/verification mapping are in ../TASK.md. This is a combined
pre-implementation gate; source remains the accepted p02 artifact. All decisions below are proposed.

## 1. One company-agent creation transaction, no automatic desk

Keep `create_company_agent_on` as the only production creation primitive for normal creation,
library copy, onboarding and the Agent Builder. Under its existing actor account→company lock,
insert the agent/principal, register exactly `agent.slug` in `addresses`, apply direct settings,
publish the agent revision, compose/publish an autonomous workflow and bind/select it on
`AddressTarget::Principal(principal)`. Place in department/role last, preserving sorted desk gates.
The address's existing native trigger provisions the principal's lifetime canonical email binding.
Any collision, missing keyed model, publication or placement failure rolls back every resource.
There is no automatic channel, `agent:{id}` command row, alternate address or forwarding path.
Library definitions alone remain unaddressed and unbound.

Refactor responsible native provisioning code into workflow composition/publication and typed
binding/selection, used by principal and shared-desk provisioning. Shared desks keep their ordinary
reply settings and department provisioning. Avoid duplicate publishers or principal-only workflow
engines. `CreatedAgent` returns the agent and its typed principal id; internal creation may also
return typed workflow/version/binding identities. No desk id is synthesized for API/onboarding.

Agent slug and principal address stay equal. Native address validation refuses a mismatched agent
slug; native agent-slug update synchronizes its existing address in the same transaction, so a
taken slug aborts the entire rename. Keep principal settings revision fencing and canonical-binding
endpoint synchronization. A rename neither changes the lifetime principal/binding nor retargets history.
Test raw SQL as well as application writes; fixtures with deliberately noncanonical agent slugs
must use production provisioning or be explicitly updated to the new native invariant.

## 2. Persistent ownership and safe unused deletion

Add nullable `workflow_definitions.owner_agent_id`, with a tenant-scoped FK to
`agents(company_id,id) ON DELETE CASCADE`, and a unique non-null owner per company. This records
ownership of the one automatically provisioned direct workflow, independently of its current
selected binding. Explicit shared-desk workflows remain unowned. Record ownership in the original
creation transaction; user draft updates cannot assign/reassign it. Native immutability prevents
changing that identity after creation. Do not infer ownership from title, selected binding,
UUID shape, slug, or old provisioning command JSON.

Keep existing company→agent deletion locks and current authorization. Before retirement, refuse
if the principal has any direct thread or any retained run; no cleanup commits on refusal.
Remove the principal's workflow bindings/reply selection in the same transaction. Deleting the
agent then deletes its owned definition and own agent revisions by native cascade, whose existing
immutable-row guards allow parent teardown. Change only the agent_revisions→agent delete action
to cascade; retain every incoming revision/version/run/history/manifest/capability FK and guard.
External bindings to the owned workflow, retained runs, history or publications that reference an
agent revision/version therefore abort the whole delete. Do not delete external references or
broaden cascade actions on their FKs to make deletion succeed.

An unowned/shared definition is never deleted by this operation. Agent namespace retirement,
principal demotion, address endpoint retirement and follow-reviewer refresh remain transactional
and keep their current account/company order. The principal's archived identity is not live
authority; no physical principal deletion or historical ownership transfer is required. Raw parent
delete must retain reference constraints, and application tests assert rollback of all resources
when a retained reference refuses. Map real native conflicts to actionable delete errors.

## 3. Builder and presentation contracts

Replace builtin `create_agent_channel` with `create_agent`: existing agent/model/description/
capability/department/role fields create only the direct-addressed agent. Desk reply mode/custom
steps/name/slug belong to separate `create_desk_for_agent`, which provisions an explicitly named
shared desk for an existing company agent through the same native shared-desk code. No same-slug
default-desk branch. Preserve action idempotency, original-root requester authority, capability
publication immutability, bounded schemas/results and placement last. Retrying either action
returns its original identities; competing claimants produce one result.

Update enum parsers, exact builtin allowlists, schemas, snapshots, prompt, samples and test
inventory together; no alias or old decoder. Company-agent directory/listing/department roster,
settings and onboarding show the canonical principal address. Retain the separate explicit
"Create assistant channel"/shared desk UI action. Department desk displays remain desk-specific.

## 4. Relay sender authority belongs to the authenticated producer

Keep a typed source `AddressTarget` and add explicit authenticated sending-principal provenance;
never derive an agent's authority from its owner's account or an inbound From string. Reuse
trusted `AgentToolOrigin` for tool-produced messages, and the exact terminal
`channel_reply_proposals.execution_id`/agent-history exchange for actual agent final replies.
A direct agent binding may speak as its own target principal even for a pure workflow final.
A pure desk workflow does not acquire an arbitrary agent identity from its bundle or department.

Carry the proven agent principal through `MessageRoutes`/planned canonical author and frozen
publication. Persist it as the canonical message author using existing `MessageAuthorWrite`
variants. Validate it against the actual same-tenant frozen agent tool origin, terminal agent
execution, or direct-target binding when writing; native deferred checks independently refuse a
forged agent author on a workflow message. Ordinary non-agent workflow messages remain system
authored. The canonical author persists after producer-run retention, so no new sender registry
or live-run pointer is needed for later relay.

`authorize_relay` reads the exact stored delivery/part through a purpose-specific application
port before resolving recipients. It verifies company, frozen source target/From, Message-ID,
recipient and content against the proof. From must be the source desk authorized by that run's
binding or the actual sending agent's own current principal address; never another agent's
address. The sending agent principal must still be live in that company. Return the authenticated
principal context, using Member-equivalent team status plus its own grants; do not substitute a
person principal. A non-agent system sender has no invented team/member/grant authority.

Rename `IngressOrigin::InternalChannel` to `Internal`, carrying source target, optional proven
agent principal and exact delivery proof. Use that principal for attribution and participation
on the receiving side. Remove internal desk ACL bypass: ordinary `participant_access` decides,
including derived department grants. An agent member of a members-only department desk succeeds;
an unrelated agent fails. Agent→private-agent mail is team traffic; personal targets keep the
person/owner policy. Non-agent system mail does not borrow an agent's grants. Desk email sender
syntax is still permitted for its authorized binding, without impersonating the desk's owner.

Extend `message_internal_relays` from required source_channel_id to exact-one source channel/
principal columns, plus authenticated sender when present. Its native guard proves exact
delivery/part/canonical author/From/recipient/content and current principal/target eligibility;
redelivery checks the complete proof shape. Guard before durable recipient effects and recheck
inside receiving commit with current source/target policy and ordered locks. A malformed,
foreign, retired or revoked source refuses atomically with no message/intent residue. The
identity-key-before-principal lock prefix remains; acquire source/target principal rows in one
sorted set. Source/target binding updates and account edits must not invert this order.

Hop count/bounded typed trace stay p02's contract. A principal and desk sharing a UUID are
different hops; a repeated exact typed target is a cycle. Keep context suffixes, whole-message
unknown-address privacy, spam/authentication and public-desk/private-agent independence.
Preserve authenticated notification origin inheritance through the proved delivery part and
sealed source message even after producer-run retention; never copy origin from subject/header.

## 5. Private escalation notices use the actual principal route

Replace `workflow_escalation_agent_route`'s `agent:{id}`/desk lookup with the live agent principal,
its current canonical transport binding, selected direct reply binding and exact configuration
revision. Preserve enabled/current agent revision, active binding, run-as account and message
trigger requirements. No first binding, default desk, fake account or missing-route fallback.
Route eligibility checks current run-as company/direct-target/source content authority.

The notice projector retains hint→lock→reread→source/event-fence→projection revalidation→one
canonical private message/intent→receipt→event completion in one transaction. Use bounded shared
principal row lock in place of the desk admission gate, then sorted real required accounts
`FOR SHARE NOWAIT`, then company `FOR NO KEY UPDATE NOWAIT`. On busy or stale route, roll back
and release every lock before the existing separate fenced queue backoff/Deferred transaction.
Role writers keep company→principal ordering; NOWAIT on the opposite notice suffix prevents a
cycle. Cover both orders and a real three-party account/role/notice interleaving.

Missing/retired/ineligible route records the existing original-case recipient failure and wakes
assignment. It is not permanent busy and creates no recursive case. Receipts/notice-target seals
pin principal_id rather than desk_id, retaining exact binding/revision/agent/message/intent.
Use principal-aware intent FK uniqueness and exact tuple checks; no nullable membership pin.
Retain immutable origin, zero-or-one targeted handling root, explicit private delivery policy,
exact notice-derived transport Message-ID, lease/account/source/withdrawal and payload guards.
Re-inventory actual role-refusal producers per C004; samples remain authoring/scripted validation.
D2/r2 personal source membership-instance and recipient-key semantics are unchanged.

## 6. Verification and failure behavior

TASK's AC1–AC6 mapping is binding. Tests use production-created agents, real native constraints,
actual queue/projector/admission/relay commits and competing claimants. External recording
provider/scripted model remain named stand-ins, not remote delivery proof. Required cases include:

- Each real creation entry point, slug collision/rename race, failed final transaction rollback,
  one active direct binding and no automatic desk/agent command; scripted address→run→reply→queue.
- Unused deletion and direct-thread/run/foreign-publication refusals with unchanged resource
  inventory, correct ownership cleanup, native cross-tenant guards and real competing admission.
- Real member/unrelated agent relay, own/other agent From, desk From bound/unbound, pure-system
  refusal on restricted target, foreign/forged proof, post-observation revocation and replay;
  exact canonical author and origin survival after producer retention.
- Actual private notice projector/admission and origin/handling-root/current-binding assertions,
  route change/retirement, account and role locks in both orders, three-party case, lease loss,
  poison-batch backoff, actual native origin guards and recursion suppression.
- Focused affected consumers, test collection/removal mapping, fresh migrations/SQLx, offline
  all-target/source_modules, format/whitespace and boundary/fixture/docs gates. Preserve failed
  evidence and baseline disposition. No thresholds raised and no full-plan green before p04.
