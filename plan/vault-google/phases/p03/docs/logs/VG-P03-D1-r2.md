# VG-P03-D1/r2 proposed architecture (VG-P03-AG1-R1)

One cohesive phase batch. The runtime host capability captures owner metadata read through a private grant-metadata port; owner membership is checked against that stable current account owner, never against a browser-supplied subject. A host binding install failure cannot authorize calls because the final host check compares the exact current connection reference. Teardown cutoff uses grant consent timestamp and pending/failed intent evidence; re-confirmation cannot race an undrained matching intent, and a completed old intent cannot invalidate later confirmation.

One cohesive phase batch. No business integration transport is enabled until06; phase03 supplies grants, actual host authority and preparation splits, with fail-closed consumers.

1. Persist module-owned integration_use_grants with internal composite account/owner FK, opaque client/binding and host teardown scope, registered app, exact canonical destination, account authorization revision, monotonically increasing grant revision, enabled/workflow-only state. Bound128 rows/account by account lock and SQL trigger, metadata-only projections50/page. Account replacement/disconnect changes authorization and invalidates existing refs; deletion cascades private grants. Revocation locks account then grant, checks owner/current revision and increments revision. Owner revoke never requires company administration.
2. Existing HTTP/MCP connections gain explicit source none/connection_bearer/integration and nullable nonsecret account/grant/expected authorization/grant refs with SQL checks. Keep existing connection-owned sources supported; never fall back from integration to stored bearer. HTTP origins remain immutable. MCP destination/auth changes clear the binding and bump existing connection/catalog identity. Host references are opaque metadata; module tables have no host FK. Host proposal stores actual company/connection revision, destination/app and proposing administrator, expires10min, at most8 live proposals/connection with bounded pruning. An authenticated owner confirms the exact named company/connection/destination/app and all registered deterministic operations; current owner membership and proposer admin are rechecked. Admin cannot confirm another owner's account. Host attachment uses CAS after module grant creation; a failed CAS leaves an unusable grant (host match required), retriable/revocable with bounded storage; no credential copies and no cross-transaction claim of attachment atomicity. No grant becomes dispatchable from a UUID alone.
3. Required application BindingAuthority port rechecks trusted owner confirmation, current membership, proposer administration and current destination/revision BEFORE module locks. It holds the host user/company/connection locks while invoking a required module GrantWriter callback, which locks module owner/account and writes/commits the grant. Host then installs the nonsecret reference and commits while still holding those same host locks. Host rollback leaves only an unusable orphan grant, never an installed source with missing consent. Module orchestration calls host authority with no module transaction open; no module-to-host lock inversion exists. Owner-consent UX/routes adapt verified session; capability/shape/destination checks live in registered adapter/registry and run at binding and final gate. API-key header comes only from code; caller-provided auth/header injection denied. Managed account compatibility checks permissions/config identity.
4. Freeze nonsecret AuthorizationSnapshot in trusted action context, including account authorization, app/destination, grant revision and connection/catalog identities; excludes payload revision, ciphertext and token generation. Deterministic step preparation captures it; restoration/replay retains the original. Common current authority and publication checks deny integration-backed generic agent HTTP/MCP tools, nested model calls and model selection; actual published workflows with deterministic steps remain supported. Derive deterministic provenance from persisted bundle/execution step, exact intent and origin (Workflow only); preserve separate Agent and ChannelFinal rules. Samples retain synthetic/scripted ports and cannot construct a production host context.
5. Split http_for_action and mcp_use into explicit owned-secret versus integration-invocation preparation results. Existing owned-auth path preserved. Integration preparation returns only metadata and AuthorizedInvocation. Runtime ExecutionContext carries cancellation and a REQUIRED host DispatchAuthority implementation as a private runtime capability, never FrozenAction/fence/SQLx on the gateway wire. Local host authority object captures the exact ActionDispatchRequest, server-minted opaque random HostAuthorityReference and immutable invocation identity. It re-reads the persisted intent, frozen digest, exact actor/company/connection, live fence/attempt/run, current bundle/step, approval and action policy on EVERY check. Compare the supplied invocation/reference/snapshot/arguments against that captured exact request; a copied opaque ref, altered digest, foreign connection or fabricated Workflow origin cannot substitute for these DB checks. Resumed attempts mint a fresh runtime context from their real current fence; no persistent authority-token service or cached approval.
6. Compose the final gate through a REQUIRED application callback: DispatchAuthority::check(invocation, module_gate) first locks/rechecks persisted host user/company/run/fence/connection/operation authority, then calls module_gate.check(invocation, current_host_facts) while its short host transaction remains open. The module callback locks current owner/account/grant, validates registry/shape/consent/status/revisions and authorize_dispatch, and commits/releases those locks. This successful combined check while both sides are locked is the linearization point; the host transaction then commits and all locks are released before business I/O. Lock order host user/company/run/fence/connection/operation -> module owner/account/grant, matching existing user deletion (which synchronously retires account payloads). Module CRUD/refresh never calls host authority while holding module locks. Module final-gate orchestration enters host with no module transaction open, and the module callback performs no host reads. No host locks during refresh/discovery; phase05 independent resolver releases its account lock before this gate. Revocation before the decision denies; effects already authorized may complete. There is no successful callback default; tests prove a host implementation cannot skip module validation in the production adapter.
7. Extend existing company/member teardown intent handling to invalidate grants by opaque scope/owner without deleting unrelated private accounts. Final gate/create deny a pending/failed matching teardown before worker drain. Membership teardown must remain effective after removal/readdition: preserve matching retirement evidence or invalidate affected grant revisions before reopening; a late worker cannot invalidate a newly confirmed later grant. Account owner retirement/deletion serializes with grants and erases credentials/grants. Internal FKs prevent dangling live module references. Host stale references are denied and can be explicitly reattached, never silently revived.

Failure behavior: typed invalid/denied/conflict/limit; no credential resolution endpoint or business I/O. Configuration discovery gets a separate owner context, cannot mint business authority and remains unavailable for integration-backed MCP until06 transport wiring. Errors/logs/HTML omit secrets and ciphertext. Source changes wait for independent D1/r2 PASS. D1/r1 retained in logs; r2 corrects a discovered inversion with existing user_lifecycle.rs/retire_owner_on. No code was authored against r1. Required callback composition preserves portable DTOs and keeps SQLx transactions exclusively in concrete adapters.
