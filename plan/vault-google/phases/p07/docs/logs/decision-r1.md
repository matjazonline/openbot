# VG-P07-D1 / r1 — bounded gateway projections and local conformance proof

Original requirements: plan/vault-google/07-integration-verification-and-operations.md, all07A–D, user targeted-only override VG-I03/r3. Depends on accepted06 source d9d84e7e35bc0a1d603f6f57bf2ac6ba5a9c95a133611bba00b432fe31533b71 and all01–05 contracts. This is a protocol proof, not a remote gateway/server or deployment.

## Decision and invariants

Add a version1, strictly bounded JSON projection vocabulary for public gateway commands and sanitized results. Explicit commands cover management metadata and static-secret submission, connect begin/callback/cancel/status, grant create/revoke, HTTP/MCP execution and owner MCP discovery; results cover only the corresponding public metadata, typed failures, catalog and mutually exclusive pre-dispatch/committed/uncertain outcomes. No private resolved credential, injection, cipher envelope, refresh token or provider client may be a result field. Owner claims are namespaced data, never VerifiedOwner. Static secret submission and callback codes are command-only sensitive inputs with redacted Debug and explicit serialization; never serialize private resolver output. Every frame has a protocol version and bounded opaque request/cancellation/dispatch identities as relevant. Use a128KiB total frame ceiling (including envelope), existing tighter domain/operation/catalog/result limits, serde recursion bounds and deny-unknown-fields. Unknown versions/types/extra fields and invalid domain values fail closed. New protocol has no compatibility decoder or staged support.

Keep runtime cancellation, genuine business/configuration authority, native BusinessDispatch/effect ownership and trusted VerifiedOwner/browser context local. Neither Tokio tokens nor host leases/session/database/workflow structs are wire fields. AuthorizedInvocation already carries only integration-owned opaque references and deadline; its existing domain validation remains required. Deserializing IDs/owner claims cannot construct VerifiedOwner or a live authority implementation. An in-memory serialization harness uses the same actual local gateway/ports, with a required trusted local context factory resolving exact dispatch/cancellation identity and deadline. It may not synthesize successful authority from payload facts or silently replace cancellation. Management/connect/grant projection claims require local authenticated context agreement before any actual call. No production listener/RemoteIntegrationGateway, remote auth adapter, distributed revocation or exactly-once claim is introduced.

Local and in-memory scenarios share actual persisted authority and native dispatch seams. Verify revoked/current/stale versions, invalid authority/owner/app/destination/schema, deadline/cancel and redaction; preserve native uncertain-send handling, no new marker or retry permission after uncertainty. Unknown protocol fails before gateway, credential or transport work. Serialization is only transport-shape/conformance evidence, not proof of a distributed protocol. Document explicit future extraction requirements including host live authority, revocation acknowledgements, durable teardown coordination, reconciliation, partitions, custody and non-root deployment.

Provider extension uses code-owned test-only registrations/adapters; production registry remains static bearer, registered API-key header and Google OAuth only. Reuse strict installation/noemail renewal fixtures and extend them with explicit custom scope-to-capability authorization mapping and isolated client identities; no vendor switch in shared workflow handlers. Provider/app payload facts cannot expand access through cache updates; consent changes increment authorization and invalidate old grants. Shared locks and durable strict pending recovery remain C001/C004, no new SQL protocol or schema. Test two app grants sharing one account, genuinely competing gateway instances/pools and strict consumed-refresh safety.

Add bounded observations using fixed event/outcome labels (cache/refresh/lock/revocation/reconnect), no dynamic credential/error/body labels. Public account/grant states remain sanitized. Sentinel tests capture provider failure results, receipts and actual tracing output; reject/redact credentials before third-party SDK diagnostic emission if such leakage is reproduced. Do not log full requests/mailbox data. Add a CI boundary checker with mutation fixtures: host HTTP/workflow consumers cannot read module tables, public DTOs cannot import host session/workflow/SQLx types, private resolver/credential types cannot derive serialization or appear in result projections. Native host authority/teardown bridge adapters remain explicit integration-owned boundary implementations; no blanket allowlist for consumer violations.

## Failure/recovery and verification

No new persistence tables, migration, lock order or dispatch ownership changes are planned. Existing module key rotation, ownership/teardown, pending-refresh and host receipts remain authoritative. New tests compose these through actual ports, deterministic barriers and owned loopback peers. No live Google credentials/provider network requirement. Targeted new nonzero integration_portability_, integration_service_contract_ and vault_google_e2e_ families; affected lifecycle/renewal/authority/gateway/HTTP/MCP/approval/sample tests, actual scoped browser fixtures, formatting/diff/offline alltargets/Clippy, fresh own migrations/SQLx, CI boundary/mutation and documentation structural checks. All07journeys must have recorded behavioral evidence; reuse unaffected accepted evidence with exact identity rather than claim novel coverage. Final07D broad/full/runtime/stack/lease suites and offers are overridden by explicit user I03/r3. Known inherited scanner failures remain separate and unchanged; no green full-suite claim.

All implementation waits for original independent B architecture PASS of this immutable decision. Reopen if an assumption is contradicted or ownership/auth/serialization contract changes materially. One whole-phase code review and combined findings correction after implementation.
