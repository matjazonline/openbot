## D1.1 Snapshot ownership and freeze point

It contains a typed bounded logical history selection: selected exchange IDs, positions and access levels, exact structured JSON inputs/outputs, eligible omission count, highest selected level, full frozen content level, conservative budget accounting. The seed is a typed bounded array of exact structured input/output Value pairs; selected identity/order/level metadata is a same-length parallel typed array. Provider text is derived canonically from those values, never accepted as unrelated caller text. The live current input remains the existing context field, never concatenated into a new logical input. No historical tool/continuation/turn metadata is stored in the seed. The full document is bounded by existing checkpoint/preparation ceilings; the seed has a separate much smaller bound below. Payloads are snapshots, so cleanup of older source exchanges cannot break replay; only this exchange's existing own-source/checkpoint/resumability lifetime pins are required. No foreign selected-exchange FK or second memory service.

After existing current-global authority -> own run/job/exchange -> owned conversation turn, select/freeze within the same existing WriteBound preparation transaction, before credentials/checkpoint/provider. Call raise_content_level_on(highest selected level) only during first freeze, then store the exact snapshot with selected_level and content_level=max(original run content,highest selected level) in this same transaction. Native freeze validation checks this classification against the now-current durable run and verified pair stamps. A rollback persists neither. Existing preparation COMMIT ambiguity proof must require the exact immutable persisted document; it may read/reconstruct but cannot select/freeze/write/raise again. Parked has no selection/provider work. Ready owns its turn; completed replay retains its old snapshot and never reacquires/releases successor.

On retries/continuations reconstruct the current immutable PreparedAgent base from its frozen manifest/step, attach the stored history selection, and require full serialized document equality. Do not deserialize mutable draft agent configuration, generate new history or silently change provider/schema/revision.
