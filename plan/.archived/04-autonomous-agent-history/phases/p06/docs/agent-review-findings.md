## AH-P06-B1-F1 — Completed exchange expiry can break accepted-output control retry

- **Context:** 2026-11-08, implement-astra-reviewed-2-2, whole06A/B code review AH-P06-B1-R1; reviewer B requested Astra/high (actual runtime metadata unavailable), worktree `/private/tmp/openbot-agent-history-h_82_5pw/worktree`, HEAD `4ab45555f8316ec7a8b1b64e8c05b77ff7d9a29d`, source `00802f0612c99b0beadd30c01cfc1bf78ad252a7d3eed9326b8fd2003a4e1110`. Links: [TASK](TASK.md), [REVIEW](REVIEW.md), [round notes](agent-review-notes.md).
- **Classification:** actionable correctness/recovery defect, **HIGH**, OPEN. Requirement 06B2/06B4 and accepted P02 same-execution Completed replay contract.
- **Evidence:** `agent_history_payload_expirable` in init schema protects a pre-deadline exchange only when its **exchange state is failed**. A Completed exchange with an accepted checkpoint whose source workflow/job later fails passes the terminal job/run predicates. Once 64 newer retained terminal exchanges exist (or company pressure exceeds 1536), it can lose its frozen preparation while the original source remains retry-safe. Existing `agent_history_lifecycle_tests.rs:103–153` proves the genuine supported shape: accept output, fail workflow, native retry, claim the same execution, prepare, reopen checkpoint as AlreadyApplied with one model call. That case currently has no cleanup pressure.
- **Affected consumer:** `agent_history/preparation.rs:100–134` reuses the matching exchange then calls `frozen::freeze_on`; `frozen.rs:20–24` returns None after expiry, and `frozen.rs:44–60` tries to select/freeze again. The native expired-row guard rejects that update (`guard_agent_history_exchange_change`), so retaining the checkpoint/source alone does not preserve this required replay path. Inspection establishes the contradiction; B has not executed a reproducer.
- **Required correction/evidence:** preserve all preparation material still required by genuine same-execution retry, including Completed accepted output after workflow failure, until the original immutable deadline/retry lifecycle closes (or prove an equally exact existing-source replay path without reselection, resetting state/order, or another provider call). Add a real native accepted-output → workflow failure → retention pressure → control retry regression; assert cleanup refuses the required copy or exact replay remains functional, identical preparation/output/order/accounting, unchanged completed exchange, no extra provider call, and expiry becomes eligible only when the replay pin is legitimately gone. Include the appropriate competing cleanup/retry case. Do not merely add an exchange-state Failed assertion.
- **Origin/lesson:** implementation and gated decision's “failed-before-deadline” shorthand missed that logical completion and retryability are separate owner facts. Candidate guidance for lifecycle reviews: derive retention pins from the actual replay consumer, including accepted results whose workflow owner has not completed, rather than treating a terminal logical-output state as non-resumable.
- **Resolution history:** 2026-11-08 OPEN in R1. Root informed; source remains frozen pending complete round.
