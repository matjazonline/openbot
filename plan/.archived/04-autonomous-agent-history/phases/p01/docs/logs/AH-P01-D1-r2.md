## One owner and boundary

The agent runtime owns history. Persistence derives identities from genuine workflow admission/claim/selected agent facts; no model/workflow input chooses a production conversation. AgentId is the existing frozen selection's AgentId, AgentRevisionId is provenance, never a stream key. ConversationId/ExchangeId/PrivateSessionId are distinct opaque typed IDs. No history for ai.classify/decision.agent; samples have sealed ephemeral identities and cannot address production storage. ## Persistent identity model (reset-only init schema)

Three narrow identity tables in phase01; durable exchange rows/capture belong to phase02, turn ownership to03, history selection/provider context to04. No placeholder active-turn/queue or fake exchange output in01.

1. agent_history_sessions: tenant-scoped opaque private session, creator principal/user provenance and immutable RelatedAssociation boundary (company, channel or exact channel/thread). Private sessions do not imply broad tenant/agent access. Current creator membership/access and current execution authority must still hold. Prefer a tenant-scoped principal FK; do not FK to ephemeral membership rows in a way that prevents revocation.
2. workflow_agent_sessions: one immutable default private session per actual root admission, linked by company/run/session and creator provenance. Fresh root without an authorized reuse gets a fresh session in the existing admission transaction, so retry/replay/lease replacement cannot allocate another. Every root may need a private fallback even if its ordinary message call uses a shared thread. Children do not acquire a parent's session; their private branch anchor is the genuine child run/admission. Missing/foreign/inconsistent mappings fail, never silently allocate during a read of old rows (database reset, no backfill).
3. agent_history_conversations: tenant+agent+trusted boundary unique stream; separate exact anchors for a canonical thread, private session, or child run. Exactly one anchor; composite tenant FKs, genuine child-parent shape and immutable scope; no level/revision in uniqueness. Child anchor is a real child run, never a caller-supplied parent ID. No reference to the conversation's first run that would erase a shared stream when that old run is pruned. No payload or expanded prompt in these identity rows. Future exchanges reference the same conversation/agent/tenant and actual execution.

Native constraints enforce scope shape, company consistency, immutable relationships and one stream/default mapping. Use unique get-or-create and exact replay, not updates that retarget a row. Current access failures propagate/refuse; no authorization-error default. No parallel agent engine, memory provider, generic strategy registry or override mode.

## Trusted public thread vs private contexts

A shared thread stream requires a genuine message-triggered root admission to an authorized actual channel/thread and a provable matching input audience. Merely supplying source_message JSON, attaching a manual run to a thread, or being a thread participant grants nothing. Derive the association/source from stored workflow/admission facts, with existing current association and agent authorization.

Determine private/unproven input lineage from the immutable compiled expressions and actual step kinds, not JSON content, slugs or model strings. Reuse/extract the existing activation input_dependencies/reference traversal, including transitive dependencies, params and rule/repeat references; preserve its current dependency semantics. A small closed provenance policy may recognize canonical root message input, context.history, pure mapping/rule transforms and prior agent output whose input lineage is provably the same boundary. Private decision/reviewer data, params, generic event payloads, external I/O or child-returned data not proven to share that audience use the run's private session. Unknown lineage defaults to private, not partial public sharing. A genuine message.ask result may share only its already enforced exact thread/question boundary; otherwise private. This choice partitions conversation access, not execution or output behavior. The private fallback is stable for that root; the same private context cannot switch to a public stream on retry. Child calls always use their own durable branch even when the same agent is executing in the parent; explicit parent input is their only inherited content. Samples never read these tables.

This is deliberately conservative: same-agent calls in different workflows share only when the actual trusted thread/audience provenance agrees. A later override feature is out of scope. A dynamic AccessLevel is not a boundary discriminator. A thread remains one stream as its ceiling changes; visibility filtering is separate. No hidden-level marker/count.

## Minimal standalone reuse through normal admission

Extend the typed normal manual/admission metadata with an optional private-session reuse reference to a prior root RunId (a distinct AgentHistorySessionRef), not workflow parameters/context or arbitrary conversation IDs. The existing start result already returns RunId, so this needs no extra session-creation API or generic store bound on every fake. Resolve that reference to the prior root's default private session under current admission authorization. Require same tenant, creator/caller and exact immutable association boundary; refuse foreign/private/child/changed-boundary reuse without revealing existence. Preserve the actual producer-supplied, persisted workflow_runs.actor_id for execution, history access and knowledge checks. A manual run executes as its authenticated starter: manual::start retains request.actor through PreparedAdmission and admission_write, even when the selected binding's run_as is a different admin. Automatic message/schedule producers explicitly choose their binding run_as at admission and persist that actor; child calls inherit the actual parent actor. Never rederive a manual run's actor/ceiling from binding.run_as, and never follow a mutable binding actor after admission. Record the private-session creator from that genuine admission actor/admitted-event provenance. An authorized reuse references the creator's attached session and exact boundary; it grants no actor substitution, additional delegation, or higher ceiling.

Automatic message/schedule/child admissions cannot supply this reuse metadata; scheduled roots allocate separate private sessions. Graphs/model outputs cannot set it. Normal admission creates the mapping only after the actual run/admitted provenance exists, in the same transaction; root rollback removes everything. Replay returns the saved session/mapping and does not allocate. An explicitly requested reuse on replay must resolve to that saved session, or conflict; a normal retry with no reuse request keeps existing replay semantics and cannot trigger another execution. Do not change old binding selection/replay/current-readiness semantics. No legacy decoder/backfill for rows lacking the new map.
