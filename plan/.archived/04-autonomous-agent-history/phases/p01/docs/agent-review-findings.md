## AH-P01-AG1-F1 — preserve the actual manual execution principal

- **Context:** 2026-11-07, `implement-astra-reviewed-2-2`, p01 architecture gate AH-P01-AG1-R1; independent B requested Astra/high (actual runtime metadata unavailable). [Review](REVIEW.md), [round note](agent-review-notes.md#ah-p01-ag1-r1--architecture-gate-changes-required), [TASK](TASK.md). Worktree `/private/tmp/openbot-agent-history-h_82_5pw/worktree`, branch `codex/autonomous-agent-history-h_82_5pw`, base/HEAD `4ab45555f8316ec7a8b1b64e8c05b77ff7d9a29d`. Decision [AH-P01-D1/r1](logs/AH-P01-D1-r1.md), SHA `5f45027f1c475f0cf43620915e89efd1ad3aa1c992ecd09cf51e63833b532732`; source `1110c5fc00a39784aab21d8f94b47d1ec5e7cdc458f72ecfabb371c1b0f9d268`.
- **Classification:** actionable architecture/authorization defect, **medium**, OPEN. Originates in the proposed decision, before history implementation.
- **Decision evidence:** D1/r1 line29 states that when binding run-as differs from starter, use admitted-event provenance for the session creator and “actual bound run-as/current agent authority for execution.” That is not the current manual execution contract. The proposed actor distinction is consequential to session authorization, agent grants and the knowledge ceiling.
- **Actual source:** `src/application/workflow/manual.rs:47–84` forwards the authenticated starter as `AdmitWorkflowRequest.actor`; `src/application/workflow/contracts.rs:140–177` retains `request.actor`; `src/adapters/persistence/workflow/admission_write.rs:7–63,122–158,198–214` writes that actor to both the actual run and admitted event. `src/adapters/persistence/workflow/agent_manifest/mod.rs:46–63` captures agent dependencies as the same actor. Checkpoint authority follows the actual run actor (`checkpoints.rs:268–294,310–337`, `agent_preparation.rs:16–43`). Current configuration `run_as` is not a replacement for that actor. The existing focused regression `knowledge_run_level_manual_uses_actual_admin_starter_and_keeps_member_refused` in `knowledge_admission_tests.rs:226–252` explicitly requires the actual manual starter's level, with ordinary members refused. Automatic message/schedule producers can supply their configured run-as through their own authorized admission paths; that does not change manual semantics.
- **Impact:** implementing the decision literally can check a different user's rights/ceiling for history or reject a valid manual caller based on another user's grants. If substituted as execution authority, it can also broaden a manual run's access. This is a prospective design defect, not an assertion that current code already leaks history.
- **Required correction:** state that history preserves the producer's actual admitted/persisted execution actor and existing current-authority/knowledge checks. Distinguish authenticated session-creator provenance from execution provenance only where the current producer genuinely distinguishes them; do not derive a manual execution actor from binding `run_as`. Retain the minimal reuse contract and its same-creator/current-access checks. Include an affected regression with an authenticated manual starter different from the binding run-as (different levels/rights), proving original execution authority and ceiling remain unchanged for fresh and reused sessions, with current revocation still refused. No source redesign is requested during this gate.
- **Instruction lesson:** observation: a generic run-as statement was applied to manual and automatic producers despite their different current admission contracts. Candidate scoped guidance: when adding authorization-bearing admission metadata, pin each producer's actual persisted actor and ceiling source, and test the manual starter/configured-run-as mismatch. Existing original01A/current-authority and AH-C001 requirements already demand preservation; no AGENTS/skill edits authorized here.
- **Resolution history:** OPEN on AH-P01-AG1-R1. Root acknowledged the mismatch and plans a revised decision plus regression; acknowledgement is not a fix or acceptance. Recheck the immutable successor decision before dependent implementation.

## AH-P01-AG1-F2 — retained session FK prevents native principal revocation

- **Context:** 2026-11-07, `implement-astra-reviewed-2-2`, p01 reopened architecture gate AH-P01-AG1-R3; independent B requested Astra/high, actual runtime metadata unavailable. Observed implementation source `fd81283df217c677856979928e35b5f2a31a7805b7547a24d95f75fa3efa006a`; proposed corrective [D1/r3](logs/AH-P01-D1-r3.md), SHA `ccdc36a566d74d5703c7c6e6d506b11167185a2c4a4882810ea018fb36a4a170`. [Round note](agent-review-notes.md#ah-p01-ag1-r3--principal-lifecycle-architecture-reopen-pass), [review](REVIEW.md), [TASK](TASK.md).
- **Classification:** concrete correctness/revocation regression, medium. Author detected before this gate; independently confirmed by B. Implementation OPEN; corrective architecture accepted below. This is not a new objection to D1/r3.
- **Evidence:** migration `20260817000000_init_schema.sql:13598–13615` gives retained session creator a required FK to principals. The principal's `(company_id,user_id)` FK to company_members has ON DELETE CASCADE (`:9868`). Thus deleting a principal or its membership now fails at commit on `agent_history_sessions_company_id_creator_principal_id_fkey`. [Actual affected run](logs/history-and-affected-runtime-05.log) has161PASS/3FAIL, all28history tests passing; [independent count/failure audit](logs/AH-P01-AG1-R3-reviewer-failure-evidence.json) confirms all three23503 errors. Tests `workflow_action_authority_revocation_contender_blocks_then_rechecks` (action_tests.rs213–242), `workflow_action_authority_sql_scope_actor_and_current_membership` (159–210) and `workflow_admit_sql_actor_revocation_blocks_new_replay_and_alias` (admission_authority_tests.rs52–65) exercise real revocation/competing authority, not obsolete fixture assumptions. `test_support.rs577–625` uses actual membership deletion and owner replacement. Do not weaken them.
- **Impact:** retaining agent session identity obstructs otherwise-supported current-authority revocation. Required original01 rights and preservation of the existing authority protocol are violated. Production member removal may demote the principal to external (`company_invite.rs549–599`), but that does not justify forbidding the separately-supported native deletion path.
- **Instruction lesson:** the referenced UUID's apparent stability is insufficient; follow its own FK/delete/conversion lifecycle before using it as a retained audit identity. Candidate scoped guidance: retained execution/history provenance must not prevent principal/membership revocation, and both application demotion and native deletion should remain verified. No AGENTS/skill edits made.
- **Resolution, AH-P01-AG1-R3:** D1/r3 is **FIXED at architecture level**. Preserve immutable historical principal/user snapshots; introduce a separately nullable tenant-qualified live reference with native SET NULL on actual principal deletion; permit only clearing the old live reference once the exact old principal is absent and every other identity/boundary/time field remains unchanged. Creation still proves both fields against the genuine admitted person principal. Historical IDs confer no rights; current persisted actor/company/member/association/agent authorization remains mandatory. No retargeting, membership pin, broad update bypass or cascade deleting history is approved. Explicit fresh migration, three original regressions and new retention/refusal/direct-update tests are required. **Implementation remains OPEN** until corrected source and targeted verification receive whole-phase code review; this gate does not mark the currently failing source fixed.
