## Declared operation and honest ownership

Add `message.ask` as a declared workflow messaging step, never a selectable agent tool. Inputs: source_message, bounded canonical content, absolute RFC3339 deadline, literal payload_schema equal to the existing MessageTriggerInput schema, and the existing optional static approval form. Its permitted respondent is the frozen source message's authenticated author principal; the source is selected through the existing authorized reply route. Reject a source without a resolvable principal; neither model-selected reviewer sets nor thread membership grants answering authority. Formal choices/review remain decision.human and protected action decisions; message.ask is a conversational reply, not a decision submission.

The workflow step returns the validated MessageTriggerInput only after an authorized reply. Its built-in action snapshot has the existing message transport-result schema: action receipt and workflow output are distinct. It uses a genuine I/O claim, action intent, fenced dispatch marker, existing Step origin, message destination, 128-per-execution slot admission and delivery ledger. No fake workflow lease, action, attempt or new publication queue. Reject Ask in message_tool_request and agent-tool registration/selection as well as SQL provenance. Existing send/reply behavior and their split-step wait.event pattern are preserved.

The question record binds company/run/execution/invocation/wait, canonical prompt/source message, expected principal and original capped deadline. Unique real wait and invocation/recipient prohibit duplicates. Immutable payload/route remain in the existing frozen action and destination; bind the question record to those exact facts with SQL guards and tenant-qualified FKs. Replays resolve the saved human wait even when transport acceptance was already recorded. No path returns an accepted transport receipt as the question step's business output.

Use the new honest attempt stop cause question_parked. Deferred fenced-completion/dispatch proof checks the real question, open event wait, source/destination/recipient, active run, exact closing attempt and original fence expiry at commit. In-app questions also park; immediate message acceptance never resolves the human wait. Cap the question deadline once by run deadline; reject elapsed values before publication. A retry observes the same invocation/wait/message/deadline and incurs no second slot debit. The step publication path retains existing account/company/run/action lock order, authority, route and knowledge-release checks, and optional private action approval before public prompt publication.

A queued canonical prompt plus its normal delivery is the durable prompt intent; no second canonical publication worker or pending-prompt table is needed. Provider I/O remains exclusively after commit in the supervised delivery worker. Explicit-action delivery aggregation continues to record transport truth independently; an event wait is never completed by those receipts.

Child questions resume the child, then existing child completion resumes the parent; only the admitted designated root may produce its final automatic reply. channel.no_reply affects only that final reply.
