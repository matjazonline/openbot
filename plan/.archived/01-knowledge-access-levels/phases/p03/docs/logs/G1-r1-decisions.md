## D1 — One level vocabulary, immutable ceiling and monotone content

Reuse domain AccessLevel and add pure `audience_level` via AccessLevel::lowest plus `may_release(content,destination)` (`content <= destination`). Keep these the sole Rust policy definitions. Named level/fact structs avoid same-typed tuples.

Init schema gains workflow_runs.knowledge_ceiling (domain/NOTNULL/no fallback), content_level (domain/NOTNULL/default0), CHECK content<=ceiling; messages.access_level, workflow_http_connections.access_level and company_mcp_connections.access_level (same domain/NOTNULL/default0). Run ceiling is part of existing immutable run snapshot. Content is deliberately excluded from snapshot equality and has a dedicated named workflow guard: it may never decrease, exceed ceiling or change after terminal state. A child's terminal level can therefore be read with its immutable terminal event without locking the child under its parent.

Persist immutable numeric freeze evidence on workflow_action_intents (`content_level_at_freeze`, `destination_level_at_freeze`, same domain/NOTNULL, explicit writer values). Range/coherence constraints and the existing whole-row immutability guard cover them. They are server facts, not part of caller ActionRequest, credentials or mutable action arguments. Do not change existing argument/operation digests or idempotency identities merely because run content later rises. Raw fixture writers must supply valid explicit facts so original negative tests still reach their intended guards.

Update persisted message/run/connection projections, fallible conversions, reads/writes and all affected fixtures coherently; numeric level serde is required on stored payloads, with no legacy defaults. Human/non-workflow messages are always PUBLIC. Canonical message insertion receives a named trusted stamp source (`Public` or scoped workflow run), derives the workflow stamp inside the same write transaction and never accepts a transport/user-provided classification. Retried already-stored messages retain the original immutable stamp; conflicting canonical identities roll back as today. Message stamps are immutable after insertion.

## D2 — Atomic admission and exact supported trigger semantics

Resolve initial levels in the existing admission transaction before inserting the run. One company-scoped reader query carries membership and level together and decodes current principal/role facts strictly, reusing p01 mapping semantics; no separate cached level lookup, unknown-state default or swallowed error. Person/External count, Agent/System do not; empty audience is PUBLIC. Distinct finite fact combinations/aggregate rows bound Rust allocation rather than hydrating unbounded party lists.

- Message trigger: current thread parties of the command's authorized source association. Validate the triggering message stamp in the same transaction. Above-ceiling stamp gives a typed `knowledge.trigger_above_ceiling` refusal with no run/job/admission partial write; integrate with existing message-intent refusal/attention materialization, never a hot retry or content-bearing error. Because the trigger body is already input, initial content is its stamp (normally human0), not an unconditional0. A valid high-stamped trigger must taint a run even if it never calls context.history.
- Manual: current level of the actual authenticated starter, while preserving existing Owner/Admin workflow-start authority; do not grant ordinary members new workflow powers.
- Schedule: current level of the configured run_as actor, not a worker or arbitrary request field.
- Child: parent's original ceiling and current content at the child-start transaction. Both step children and workflow-tool children use the existing single runtime child writer.

Actual code requires authenticated WorkflowActor/run_as and has Message/Schedule/Manual/Child trigger variants; no standalone webhook/no-actor production admission exists. Preserve those constraints. The shared automated-reader policy has an explicit absent-reader→PUBLIC case for the stated safety rule, without adding a fake actor, nullable live owner, unsupported trigger path or compatibility branch. Future webhook admission must use that same policy. Missing/invalid source association is refused through existing source authorization, never granted an owner's ceiling. Admission replay returns stored levels and never recaptures current audience/actor levels.

## D4 — One release policy/evaluator, mandatory freeze and real new-effect boundaries

Both ActionService prepare_step/prepare_tool continue through the required ActionIntents.prepare port. The PostgreSQL implementation calls ONE shared release evaluator inside the transaction that freezes a NEW immutable intent, locks/reads the run at least FOR SHARE (existing FOR UPDATE may be retained) and records the two numeric levels. No alternate message/HTTP/MCP/provisioning implementation receives its own policy copy.

Initial intent preparation is earlier than message route materialization and remote reservation. To prevent a destination change in that interval, reuse that SAME evaluator at each existing guarded **new-effect** boundary: message publication before marker/messages/delivery writes; remote HTTP/MCP reservation before a new provider entry; provisioning's existing local effect transaction. Child workflows are allowed through inherited levels, not treated as public egress. The rule is applied in one shared evaluator; boundary calls merely supply trusted action/scope and invoke it.

Use the existing company/current-actor→run→execution/job lock discipline at guarded dispatch. When intent preparation needs additional current facts, acquire the company/actor authority barrier before the run/connection rows rather than introducing a reverse company/member edge. Preserve p01 account/invite/company/member writers and existing reservation lease/COMMIT-ambiguity handling. Reuse current transaction timeouts/bounds; do not make external requests under these locks.

Replay/uncertainty distinctions are mandatory:
- Known completed marker/receipt replay returns its recorded result and does not reissue an effect or depend on later routing/level edits.
- Replayed pending intents cannot authorize a fresh low-level effect after the run has read higher content: the actual new-effect boundary always uses current run content/current destination. This conservative rule also covers previously prepared public arguments.
- A prior possible-effect marker remains uncertain/retryable under the existing protocol; do not misreport a knowledge refusal as proof that its old effect never happened or discard reconciliation state. Still prevent any newly refused provider entry. A new action with no prior possible effect gets the exact typed refusal behavior below.

The destination query is the release linearization point **inside** the freeze/reservation transaction. Read the complete bounded destination group with one MVCC statement/fact snapshot and record its minimum. A CC/level edit committed before this query is seen; a concurrent edit after it is ordered after that freeze. No new thread-writer locking protocol is introduced merely to hold a participant set until COMMIT. This avoids inverse locks with account_identity::adopt_outsider_places, existing thread upserts and principal retirement. Run locks remain necessary to serialize output/rise against action freeze. Message planning freezes concrete recipients and publication rechecks its routes; later additions cannot be silently appended to an already frozen transport plan. This point-of-freeze contract cannot recall a request already committed to transport/in flight.

Destination classifications:
- External reply: minimum of the current source thread's Person/External audience and actual external email recipient clearance. This also protects a retired/unverified source address even when an old Person party remains in a thread.
- Explicit member email: verified current company-member identity's level; absent/unverified/nonmember email is PUBLIC. Foreign/missing scoped resources fail existing authorization, not a privilege-bearing fallback.
- Internal note, in-app message/internal reply and other internal-only publication: current content, permitted with its stamp. InAppOnly delivery policy remains enforced. Phase05 supplies viewer filtering before whole-plan publication.
- HTTP/MCP: current scoped connection level. Do not freeze that trust level into workflow publication or credentials.
- Provisioning built-ins: PUBLIC, including Agent Builder operations; no matching name can manufacture authority.
- Unknown generic local action kind: PUBLIC (safe for current public fixtures), with existing resource/contract authority still required; never silently grant a high-level destination.
- Fan-out: use the minimum over all destinations and refuse the whole operation before any marker/send if one cannot receive it. No partial sends, regeneration or sender override.

Generic CRUD payloads cannot bypass it. Owner can set any connection level; admin cannot touch a higher current target or request above self; members cannot change levels.

Every implementation/mock states the required behavior. Render capped options from current joint facts, preserve failed input/progress/CSRF/escaping and refresh authority after writes.
