Validate the effective choice against the discovered native provider capabilities. Saving a profile with an agent must not reject an unused fallback permission choice.

## Persisted reference / bounded delivery

The portable versioned bundle is a deterministic projection of the captured immutable published revision: full agent instructions, complete skill directories/metadata with canonical base64 and executable intent, and explicit permissions. It has no credentials, ambient paths or timestamps. Existing 1MiB published-definition bound is retained; rendered bundle JSON has a 2MiB bound with a maximum-valid-projection CI guard below75%. A profile's optional agent FK is company-scoped. Session capture uses all-or-none agent/revision/digest columns and a composite company/agent/revision FK. References use deferred NO ACTION rather than RESTRICT/SET NULL so company cascade deletion remains valid; agent/revision deletion with retained session history is rejected. No init compatibility migration; reset only the phase-owned disposable databases.

Add an operation-scoped machine-authenticated read-only GET endpoint for the captured bundle. Authenticate current installation, credential generation, connection generation/owner and unexpired machine lease without incrementing generation or acquiring a new WebSocket connection. The endpoint checks company, exact operation/session/machine association and the operation's original admitted actor plus live company/agent/skill/grant authority. It never selects the profile's current agent or filters a revoked bundle. Conditional requests (ETag=digest) run the same authority checks before304. A wrong tenant, credential/generation, operation, association or revoked source returns no bundle bytes. No browser/session auth fallback.

Fetch before create/send dispatch and again from required native configuration before every provider launch/resume, including queued Send-now/restart, so a cached file never substitutes for current authorization. Use the existing configured Openbot HTTPS origin, normal TLS, redirects refused, 5s timeout, cancellation and bounded streaming body; no arbitrary URL from command/model. Stop/control/poll must remain usable after grant revocation. In-flight native work already authorized can continue; do not promise atomic revocation of OS access on a trusted full-access machine.

## Plugin durable cache / positive native ownership

Keep an immutable content-addressed cache next to the plugin's SQLite journal, never in the packaged plugin, project/user AGENTS.md or ambient skills directories. Verify exact response digest and canonical schema before atomic temp-directory/rename publication. Materialize only validated regular relative files, with directories0700 and files0644/0755. Reject symlinks/special files, path traversal/case/prefix collisions and unexpected entries. Revalidate bytes/modes before returning configuration. Stable native skill names are namespaced from original name and original content digest (max64 characters); rewrite only the materialized YAML name and preserve body/assets/modes. Instructions retain original-to-native name mapping. Core verifies the exact post-materialization tree hash.

Cache has a total64MiB/128-bundle ceiling enforced before writes/effects; lack of space produces an explicit capacity refusal. Do not evict a bundle referenced by a durable session or an in-flight command. Tie ref retirement and owned-directory cleanup to existing acknowledged journal mapping retirement. Cache hits still check server authority and full local tree integrity. Missing/corrupt state is recovery-required, with no silent fallback to ambient files or partial configuration. Temporary writes are cancellable/awaited and cleanup touches only owned known paths.

Native capabilities are granted only after a positive SDK spawn receipt is durably mapped to the Openbot session. Use existing message.dispatch wait scheduling to hold first provider startup, return from spawn, durably save the positive native thread mapping, then recheck the queue. Never await spawn inside its own dispatch hook. The required configuration callback resolves the positive mapping and verifies actual native thread/project/provider/host; thread metadata is never capability authority. Unrelated ordinary threads receive no Openbot configuration. A managed thread without its positive mapping is refused. A lost configured-create receipt remains uncertain/held: do not recover capability ownership using editable metadata and never replay the mutation. Existing unconfigured recovery semantics remain unchanged.
