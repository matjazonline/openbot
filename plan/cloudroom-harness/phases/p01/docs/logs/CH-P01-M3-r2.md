## Decision and observable behavior

Expose one static public Cloudroom plugin tool, `openbot_company_mcp`, with list/describe/call/status operations. The actual plugin callback receives trusted thread/project/signal context from Cloudroom, looks up its durable positive native mapping, freshly checks Openbot authority, and selects only the immutable published agent's MCP aliases. Unmapped/unconfigured/foreign threads get an explicit refusal. Static registration grants no company capability to ordinary threads.

List and describe expose frozen schemas and aliases. Call takes only an alias and bounded object arguments. Identity comes from authenticated native turn/call context, never a model-generated request key. Status takes a returned opaque broker-call id as a reference, never as authority. The active native tool promise stays open while its real MCP workflow waits for approval; it returns only an effect result or an explicit terminal/unknown/cancelled outcome within its absolute bound. It does not return a nonterminal “pending, continue later” result that would let the originating native turn complete while dispatch remains authorized. Existing Openbot approval/run views show the human approval and its link during the wait. Completed MCP error envelopes remain MCP errors, unknown effects remain reconciliation-required, and transport failures never become successful model text. No credential, arbitrary endpoint, connection selector, reviewer, workflow identity or originating-operation selector is accepted from the model.

Each call is owned by a genuine, atomically admitted Openbot workflow running the existing `mcp.call` step. Openbot's normal worker obtains the real workflow job/lease/fence and executes existing McpActions and reviewed action gateway. The native proxy never manufactures WorkflowFence/AgentToolOrigin, borrows a fence from an unrelated run, directly decrypts a credential, or calls a remote MCP service itself. Manual native sessions and workflow-created native sessions both work.

Ordinary non-native invocations may lack the descriptor; Openbot's proxy requires both bounded nonempty ids and refuses absence. Resolve `(installation,thread,turn)` to EXACTLY ONE durable CommandRecord with a positively observed native turn id and its immutable session/harness/operation. The plugin durably records native invocation intent keyed `(installation,thread,turn,call)` and its exact originating operation/session/harness/alias/argument digest BEFORE an admission POST. Each replay consults that immutable intent even if the thread's current pointer changed. The server has a company-scoped UNIQUE native invocation key independent of operation_id, and refuses any attempt to bind that key to another operation or content. Response loss/restart retries that exact identity only and obtains the same allocated broker-call id/run. The client-generated model/tool arguments cannot overwrite it.

A repeated old native call id returns its original retained result/terminal/unknown state, or an explicit collected-payload state, never a new workflow under B. A fresh native tool-call id is a new explicit invocation, not an automatic retry of an old effect.

Use bounded same-origin HTTPS authenticated transport with no redirect, bounded streamed body, AbortSignal and independent request deadlines. The static proxy schema/instructions stay small; per-alias full schemas come from describe. Journal intent identity survives pointer updates, queued turns and restart, and pins its exact source CommandRecord while live or unresolved. Bound the new local intent table at4096 records and8MiB of logical encoded state, within the existing journal disk budget; reject capacity before admission. Store identity/content digest and broker reference, not an unbounded argument/result copy. A resolved intent may be collected only together with its eligible source command; a later callback lacking that exact source record fails recovery before admission. Never use a newer pointer to reconstruct a collected source. The server retains the independent native invocation tombstone, so local collection cannot permit a second execution. Exercise both bounds and collected-source replay refusal.

## Authority and atomic workflow ownership

Introduce company-scoped immutable native MCP broker/call records, not a second remote-effect journal:

- Broker registry key: company, original actor, frozen agent revision, selected binding id. It points to a real private workflow/version/binding. The source is a finite one-step mcp.call graph generated from exactly the frozen reviewed MCP contract and connection. It has the original authenticated actor as human reviewer when the frozen/current policy requires approval. It cannot run a different alias/connection or accept reviewer/endpoint data from native input.
- Call identity: company, installation, native thread/turn/call ids, independently unique across native operations; allocate an opaque server call id once. Store exact originating operation/session/machine, original actor, agent revision/binding, canonical argument digest, absolute deadline and real run id. Same-identity competitors yield one call/run/job. Changed operation, content or alias conflicts. Bound64 calls per native operation and8 unfinished calls per machine under the normal machine fence lock.
- Add immutable workflow_runs.native_mcp_call_id with company-scoped deferred cyclic identity FKs to the call's actual run id. A deferred database witness requires a broker-version run to have exactly its native provenance and a matching registry/binding/revision/actor. A missing/deleted/changed call link cannot downgrade the run to ordinary workflow authority. Public admission of an internal broker version without its provenance fails. Company deletion remains possible; individual provenance cannot be removed while its run is retained.

The native API authenticates the existing machine credential/installation/current connection generation and lease without takeover, then validates the real operation/session/original actor/frozen agent selection/live skill+binding grants. Reject stopped/uncertain/recovery-required/terminal operations for new calls. A read-only status of a retained call uses the current authenticated native invocation plus the retained call id, with exact same session/harness/original actor and current read authority. It does not require its old operation to be active, renew a lease, use a newer actor's source authority, admit or resume any effect.

Prepare a sealed application-level broker admission from the selected immutable definition and canonical arguments. Validate its source with the actual workflow compiler/publication/binding contracts. Within ONE persistence transaction, follow the closed ordering protocol below, establish/reuse the immutable internal broker, and insert the native call, actual run/bundle/binding revisions/root budget, first execution/job and native provenance before commit. Reuse/extract the real admission writer instead of calling an already-committed external admission and attaching provenance later. Any failed source, grant, quota, insert or witness rolls everything back. A worker cannot observe an unlinked run/job.

Internal broker definitions are implementation records: exclude them from authorable/selectable definition/binding listings, reject public mutation/archive/delete and public admission without native provenance, and retain normal human-readable run/approval audit views. Ordinary workflow behavior and public actor authorization remain unchanged. All readers/writers of the internal registry discriminator must receive explicit dispositions; do not rely only on route-level hiding.

## Structural identity, native read, dispatch and historical reconciliation

Four purposes have separate explicit entry points; never call the live dispatch check from a historical origin restore:

1. **Structural provenance** in shared origin reconstruction (`agent_origin::authority_on` and its actual callers, including `action_reconciliation::restore_on`) verifies the immutable run discriminator, exact call/broker/version/actor/session/agent revision/binding/contract/argument identities and FK witness. It uses retained frozen facts; it does NOT require the original actor's current membership, a live machine/connection/native operation, an active parent or an unrevoked grant. Missing or changed provenance always refuses; an ended owner is not missing provenance.
2. **Current native-client read authorization** at list/describe/status/result APIs verifies the current credential/generation/lease, current actor membership and session/harness/capability read authority. Retained lookup also requires the original actor to equal the authenticated current invocation actor and obeys existing workflow knowledge/view restrictions. It never dispatches. Native clients lose this access when revoked, while authorized operators retain their independent historical review path.
3. **Live effect authorization** at actual action preparation/freeze/credential opening/reservation/final dispatch verifies structural provenance AND original native operation/turn ownership, original actor/source authority, session/machine/credential state, deadline/cancellation, exact frozen agent binding and current connection/review/grants. Hook the existing real gateway preparation/use/reservation paths, not a new direct client. It also applies after discovery and before an existing not-applied action could be tried again. Original operation completion/stop/expiry or parent authority loss forbids every later effect; a newer invocation does not replace it.
4. **Operator historical reconciliation** uses the existing reconciliation service's current operator/company/association/resource/knowledge authority plus structural frozen origin. Original actor removal, machine revocation, operation/parent termination or client disconnect does not block an otherwise authorized operator recording the historical applied/not-applied/unknown outcome. This never directly dispatches. Applied returns a recorded receipt; unknown remains reconciliation-required; not-applied does not restore native liveness. Any later execution still passes purpose3 and therefore cannot redispatch after revoked/ended ownership. Unauthorized operators/reviewers are refused.

The action remains a real workflow action with mandatory native provenance. Use the frozen reviewed operation version/schema/policy; current company MCP grant, review, agent binding grant and original actor/source authority remain live for effects. Credential rotation is resolved solely by existing encrypted connection/integration credential use. Preserve endpoint validation, bounded discovery/schema checks and approval/reconciliation rules for bearer and integration-owned connections. Native/model/browser payloads never contain plaintext tokens.

Use existing durable approval submission/resolution and workflow polling, with the original actor as configured human reviewer when required. Full native filesystem permissions do not bypass MCP policy. During approval the native tool promise remains pending, so its original operation/parked source remains live. An abort, explicit stop, deadline or native turn completion observed unexpectedly cancels dispatch eligibility; a later approval cannot revive it. Existing approval views/notifications expose the actual decision; no event stand-in is accepted as approval.

Conservatively classify broker arguments/results at the original actor's current access ceiling with content_exact=false, carrying a workflow-native parent's stricter source ceiling when applicable. Do not label externally generated arguments an exact low-classification capture. Existing review/view guards still apply.

## Closed cross-owner ordering and propagation protocol

Avoid blocking cycles rather than imposing a new company-first order after an existing run fence. The following dispositions are part of the decision, not optional implementation advice:

| Entry | Ordering/allowed waits and propagation |
| --- | --- |
| New native admission | Authenticate/observe ids without owner locks, then existing account/company/actor/association authority, originating workflow owner when applicable, agent publication/source/grants, machine fence, native operation. All newly coupled owner acquisition is nonblocking under the contention rule below. Insert NEW broker run/execution/job/provenance after these checks; these unpublished rows cannot be owned by a worker. Reuse registry records as immutable reads; replay/status never locks an existing broker run while native locks are held. |
| Native status/replay | Current native read authority in its existing source-before-machine order, then MVCC reads of retained immutable call/run/receipt facts. No existing broker run/job lock is acquired while holding account/company/native locks. Recheck authority before release; status cannot resume work. |
| Broker action preparation/dispatch | Keep actual existing workflow account/company authorization where already required and run -> execution -> job/attempt fence order. Structural restore acquires no current native owner locks. The added live native check uses exclusively nonblocking owner locks (including account/company/originating run/source/native owners if absent), so it never waits in an order opposite admission/control. Hold successful native authority locks through the existing reservation/final authorization transaction. Never wait for an original workflow owner while a broker owner is held. |
| Broker lease claim/validate/renew | Preserve existing run-first workflow fence/capacity order. Added native liveness is a bounded nonlocking authoritative read of committed owner/cancellation/deadline/source state; it does not acquire account/company/machine/originating-run locks. A false result refuses ownership/renewal and cancels and joins actual work under existing lease machinery. Immediate pre-effect protection still comes from the locked live dispatch check. |
| Native observations/stop/expiry/revocation | Preserve current account/company or machine -> operation transactions and operation-only expiry. They update only their existing native state, never acquire a broker/originating run lock and never call workflow cancellation while native locks are held. Their committed invalidation is itself durable evidence used by live dispatch/heartbeat and the bounded sweep below. |
| Native tool abort/cancel API | Authorize the exact originating native call and commit desired-cancel on that call only, without locking a broker run. Abort signal also ends the client wait. Never infer not-applied from cancellation. Server deadline and sweeper remain backstops after network loss. |
| Original workflow cancellation/completion | Keep existing parent/run tree ordering and state transition. Do not acquire a native/broker lock from inside that transaction. Committed source retirement is visible to native/broker liveness checks and the sweep. |
| Broker cancellation propagation/sweep | Extend existing bounded workflow maintenance to select ineligible native broker runs with run-first SKIP LOCKED, then existing execution/job/cancellation order. Eligibility reads committed native/source facts without owner row locks. No native -> run updates/triggers or nested account/company acquisition. Cancel parked/queued runs; stop and await active work through existing heartbeat/fencing. Existing possible effects remain unknown/reconciliation, never safely retryable cancellation. Failed sweep candidates get existing bounded backoff/terminal handling; a poison batch cannot hot-loop. |
| Historical reconciliation | Keep existing current operator/account/company and run/execution/job ordering. Add structural provenance only. No original actor/company membership lock, live native lock or parent-owner lock is added. Recording history cannot authorize another effect. |
| Retention | Native retention excludes any call still owning retained broker work/reconciliation and never locks a broker run. Workflow retention uses run-first -> its native call row, performs no native machine/operation/parent lock, and atomically retires only resolved terminal payload/provenance as below. The call-cancel writer never takes a run lock, so this row order creates no reverse edge. Company deletion follows existing cascade/serialization; deferred company-scoped FK witnesses are validated at commit. |

**Contention rule:** every NEW cross-owner lock acquisition that could invert an existing order is `NOWAIT`, including nested helper locks. Reuse authoritative validation under a scoped zero-wait equivalent only if every helper is audited; do not let an opaque blocking helper acquire another owner. Distinguish contended from revoked/invalid. Before first dispatch, return a controlled busy/no-new-dispatch outcome (or existing bounded workflow backoff where available); do not hot retry, silently default authority, or consume an approval. An already possibly dispatched action remains unknown/receipted according to its ledger, even if the new check is contended. No SQL transaction spans remote I/O. Use existing bounded lock/statement deadlines as an additional backstop, not as evidence that a blocking lock cycle is safe.

This protocol leaves ordinary workflows and B2 native lifecycle entry points unchanged except explicit eligibility/pinning predicates. Added cross-owner wait edges are forbidden; new run rows are not shared until commit. Prove these dispositions with actual competing transactions, not only sequential same-key tests.

## Deadline, cancellation, replay and retention

A call has one absolute deadline, min(native operation deadline, admission time+15min); retries, status and restart never extend it. The native tool Promise remains pending until terminal/result/unknown or that bound. Each Openbot HTTP request is independently bounded to at most15s; bounded polling with backoff serves the same native call intent. The actual pinned daemon tool transport already awaits a streamed response under its real signal; do not detach or inject an unadmitted continuation turn. No nonterminal pending result is returned to let the original turn retire. If any real provider/transport has a shorter deadline, honor the shorter cancellation and stop dispatch rather than detaching work. The native operation stays active while its tool awaits; normal completion can follow only after its admitted MCP calls stop waiting.

On deadline/abort/turn completion, desired cancellation and the native committed owner state revoke future dispatch immediately. An approval arriving afterward cannot authorize an effect. The existing effect ledger determines applied/not-applied/unknown; there is no automatic new call, request identity or workflow after timeout/unknown. Read/schema/result payloads fit existing budgets and at most2MiB at the native boundary; an oversized retained result gives explicit result-too-large/read-link without truncation or replay.

Retained status across a later turn is READ ONLY via the opaque call id and same actor/session/harness/current read authority. A replayed old native `(turn,call)` always addresses its original intent, even after operation pointer B, cancellation or local/server restart. It may recover an existing result/unknown/collected state; it cannot make B the owner or extend A. If the originating operation ended, its pending effect is cancelled/reconciliation-required rather than left eligible for later approval.

Active, parked or reconciliation-required calls pin their live native origin and broker run/provenance. Once both owners are resolved/terminal and the normal retention age is met, the existing run-first workflow collector may remove large action/run payload and transition the native call to an explicit tombstone in the SAME transaction. Keep immutable native invocation key, opaque call id, originating operation/actor/session/harness identity digests, original run UUID, content digest and terminal outcome. The live run FK is nullable only in that retired state, with a deferred witness proving the corresponding actual run no longer exists; it cannot be detached from a retained run. Native operation identity/tombstones remain the parent of call identities; payload/session cleanup waits for all live pins. The retired state cannot be admitted again and returns payload-collected, not an empty success. Preserve frozen broker definition/version references while live runs need them; collect unreferenced large artifacts using the existing workflow/publication retention rules. No collector holds native-owner locks while acquiring a run lock.
