## Decision and observable behavior

Expose one static public Cloudroom plugin tool, `openbot_company_mcp`, with list/describe/call/status operations. The actual plugin callback receives trusted thread/project/signal context from Cloudroom, looks up its durable positive native mapping, freshly checks Openbot authority, and selects only the immutable published agent's MCP aliases. Unmapped/unconfigured/foreign threads get an explicit refusal. Static registration grants no company capability to ordinary threads.

List and describe expose frozen schemas and aliases. Call takes an alias, bounded object arguments and caller-generated request_key; status uses the same request_key. That key identifies one logical invocation and is never authority. Reusing it with another alias or arguments conflicts. A pending approval is reported truthfully with its existing Openbot run/review link; a later status/retry uses the same key. Completed MCP error envelopes remain MCP errors, unknown effects remain reconciliation-required, and transport failures never become successful model text. No credential, arbitrary endpoint, connection selector, reviewer or workflow identity is accepted from the model.

Each call is owned by a genuine, atomically admitted Openbot workflow running the existing `mcp.call` step. Openbot's normal worker obtains the real workflow job/lease/fence and executes existing McpActions and reviewed action gateway. The native proxy never manufactures WorkflowFence/AgentToolOrigin, borrows a fence from an unrelated run, directly decrypts a credential, or calls a remote MCP service itself. Manual native sessions and workflow-created native sessions both work.

## Authority and atomic workflow ownership

Introduce company-scoped immutable native MCP broker/call records, not a second remote-effect journal:

- Broker registry key: company, original actor, frozen agent revision, selected binding id. It points to a real private workflow/version/binding. The source is a finite one-step mcp.call graph generated from exactly the frozen reviewed MCP contract and connection. It has the original authenticated actor as human reviewer when the frozen/current policy requires approval. It cannot run a different alias/connection or accept reviewer/endpoint data from native input.
- Call key: company, native operation, request_key. Store exact session/machine/installation, original actor, agent revision/binding, canonical argument digest, absolute deadline and real run id. Same-key competitors yield one call/run/job. Changed content conflicts. Bound64 calls per native operation and8 unfinished calls per machine, checked under the normal machine fence lock before admission.
- Add immutable workflow_runs.native_mcp_call_id with company-scoped deferred cyclic identity FKs to the call's actual run id. A deferred database witness requires a broker-version run to have exactly its native provenance and a matching registry/binding/revision/actor. A missing/deleted/changed call link cannot downgrade the run to ordinary workflow authority. Public admission of an internal broker version without its provenance fails. Company deletion remains possible; individual provenance cannot be removed while its run is retained.

The native API authenticates the existing machine credential/installation/current connection generation and lease without takeover, then validates the real operation/session/original actor/frozen agent selection/live skill+binding grants. Reject stopped/uncertain/recovery-required/terminal operations for new calls. A read-only status of a retained call remains subject to current machine/session/actor/capability authority; it does not renew a lease or make a new effect.

Prepare a sealed application-level broker admission from the selected immutable definition and canonical arguments. Validate its source with the actual workflow compiler/publication/binding contracts. Within ONE persistence transaction, lock current authority in the existing company -> agent publication/source/grants -> machine/operation order, establish/reuse the immutable internal broker, and insert the native call, actual run/bundle/binding revisions/root budget, first execution/job and native provenance before commit. Reuse/extract the real admission writer instead of calling an already-committed external admission and attaching provenance later. Any failed source, grant, quota, insert or witness rolls everything back. A worker cannot observe an unlinked run/job.

Internal broker definitions are implementation records: exclude them from authorable/selectable definition/binding listings, reject public mutation/archive/delete and public admission without native provenance, and retain normal human-readable run/approval audit views. Ordinary workflow behavior and public actor authorization remain unchanged. All readers/writers of the internal registry discriminator must receive explicit dispositions; do not rely only on route-level hiding.

Anchor it in the existing shared action-authority path using the immutable run discriminator, so all entry points require the link and exact selected binding/contract/arguments. The relevant existing boundaries are agent_origin::authority_on/current_on, action_authority::load_on, McpActionAuthority::lock_current and mcp_use. Follow their actual callers before refactoring. Recheck after remote discovery and immediately before dispatch through existing gateway hooks. Credential rotation is resolved only by the existing encrypted credential/integration path at use time. Preserve existing endpoint validation, bounded discovery/schema validation and approval/reconciliation rules for bearer and integration-owned connections. Machine/browser/native responses never contain plaintext tokens.

Use existing durable approval submission/resolution and workflow polling, with the original actor as configured human reviewer when needed. Full native filesystem permissions do not bypass MCP policy. On read/review, retain current company membership and knowledge classification. Conservatively classify broker arguments/results at the original actor's current access ceiling with content_exact=false, and carry a workflow-native parent's stricter source ceiling when applicable; never mark externally generated native arguments as an exact low-classification capture. Existing review/view guards still apply.

## Deadline, cancellation, replay and retention

A call has one absolute deadline, min(native operation deadline, admission time+15min); retries, status and restart never extend it. New calls require a live active operation. HTTP waits are bounded (at most15s per request); the plugin may poll within a bounded60s tool invocation, then returns truthful pending state plus the same key. Reads, schema responses and MCP results are bounded to existing action/transport budgets and at most2MiB at the native boundary. If a retained result cannot fit, report explicit result-too-large/review-link without replaying or truncating it.

Operation/session stop, cancellation, expiration, machine/credential revocation or loss of originating workflow authority prevents every later dispatch. Propagate durable cancellation to linked unfinished broker runs using existing workflow cancellation/lease fencing and heartbeat paths; connect the plugin's tool signal to a best-effort authenticated cancellation request and keep the server deadline as backstop. Connection loss alone never invents success or retries an uncertain remote effect. Calls whose remote dispatch crossed the effect boundary retain the existing action gateway's unknown/reconciliation state; do not convert those to safely retryable cancellation.

Replay of the exact key returns the existing run/call status/receipt only after live authority checks. No automatic second call, new run or new request_key is generated after a timeout/unknown result. Idempotency identity/provenance outlives collected payload so expired/collected ids cannot execute again. Bound cleanup by existing native operation/session retention and workflow run/action retention; active or reconciliation-required calls pin their owning native records. Preserve company cascade and do not collect provenance before either owner.
