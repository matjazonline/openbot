# CH-P01-M1/r1 — skill directory foundation

Original requirements: implement instructions, skills, MCP and permissions on an Openbot agent for Cloudroom; user explicitly clarified that a local harness such as Claude Code can have scripts inside the skill directory. Prior requirement: full access by default. This decision covers the stable skill-bundle foundation; it does not accept an unimplemented native execution or MCP bridge.

## Scope and canonical representation

Reuse the existing company/library Skill and agent skill assignments. Add required `files` to Skill and frozen SkillSnapshot, with regular supporting files `{path, content_base64, executable}`. SKILL.md remains the existing `instructions` text, so there is one source for its text, not a second contradictory file. A ZIP import retains the complete SKILL.md bytes (including frontmatter), all regular supporting file bytes, relative paths, and executable intent. A text-only skill remains a valid first-class skill and native materialization generates frontmatter around its existing body. Preserve instruction bytes on writes rather than stripping meaningful file whitespace. Full SKILL.md frontmatter is retained and validated; require its name to match the skill slug to avoid native-directory identity drift. A plain instruction body has no frontmatter and uses the stored slug/description when materialized.

Supporting files exclude the root SKILL.md (case-insensitive). All paths are relative portable ASCII paths, at most240bytes, no empty/dot/dot-dot segments, absolute paths, drive prefixes, backslashes or control characters; reject case-fold collisions and file/directory prefix collisions. No symlinks, hardlinks, devices or special files. File bytes use canonical standard base64; executable is a boolean mapping only to0644/0755 at materialization. Bounds:64 supporting files,256KiB per file,512KiB total decoded assets. Existing16KiB instruction bound and1MiB total published agent-definition bound remain unchanged and fail early. Import ZIP input has a dedicated bounded2MiB route, bounded entry count, bounded decompression and supported compression methods; it never extracts untrusted paths to the Openbot filesystem. Existing form/body limits remain unchanged. Use already locked zip2.4.2 with explicit minimal features, no dependency upgrade.

## Persistence, ownership and frozen content

Edit the init schema and use fresh disposable databases. Add `skills.files JSONB NOT NULL DEFAULT []` (empty assets means a text-only skill, not legacy decoding). Add DB constraints/function validating array/type/path/base64/mode/byte bounds and uniqueness; test parity with Rust cases including tenant-scoped copy/update. Carry files through SELECT, INSERT, UPDATE, library copy, SkillWrite and frozen publication capture. Existing assignment ownership, live revocation and publication locking remain unchanged. No new queue/concurrency protocol is introduced in this batch.

SkillSnapshot adds description and files so native materialization has the full bundle. They participate in the existing canonical published-agent content hash. Subsequent live edits must not change admitted/published files or executable flags; revocation remains live through the existing assignment/grant authority. Hosted rendering still uses skill instruction text and does not gain a filesystem or execute uploaded scripts. The native runtime deployment is a later dependent cohesive batch, not an assertion made by this foundation.

## Authoring

Keep current text/metadata editing and preserve supporting files when commands omit their replacement; explicit empty file arrays clear them. Add company and operator-library ZIP import/update and download surfaces using existing owner/operator authorization and browser origin/CSRF protections. Display asset paths, sizes and executable state. Import parses the root SKILL.md metadata for creation; one common directory wrapper is allowed, every entry is validated before normalization, and multiple candidate skill roots are rejected. Existing library copying includes the entire bundle. Save/import controls show pending and failure feedback. JSON writes expose the same canonical supporting-file representation.

## Failure and verification

Reject malformed/bounded/unsafe bundles before persistence or native execution. Do not partially overwrite a skill on failed import, JSON write or validation. No secret-bearing logs, arbitrary filesystem writes or process execution during import. Round trips must distinguish original and updated binary bytes, nested relative script imports, and executable bits; library-to-company copies are independent after copying. Test published snapshots before/after a shared edit, and unchanged source assets under a frozen revision.

Focused checks: domain bundle/archive attack matrix, source-module linkage, Skill create/update/read/library-copy/native-entry encoding, real database constraints/tenant isolation/publication freeze, owner/operator JSON+HTML import/download and rejected-save progress/browser behavior. Check current offline all-target compilation/Clippy after affected constructor updates and regenerate SQLx metadata on a fresh database. Final full repository CI/database/stock-stack/lease gate runs once after the complete requested harness feature is implemented, with affected checks after corrections. Native script execution and MCP invocation are explicit later acceptance criteria; pure archive/fixture tests do not fulfill them.

## Subsequent batch boundary

Add settings on the existing Openbot agent; local execution profiles remain machine/project/provider/model targets. Freeze the selected agent definition per session. Native deployment must use the complete directory files and run an actual relative script; no flattened prompt-only substitute. Explicit full permission is the default, lower modes remain selectable. One later architecture gate will cover native artifact ownership, current credential/MCP authority and restart/no-replay semantics before those dependent edits. No publication/deployment authorization is inferred.
