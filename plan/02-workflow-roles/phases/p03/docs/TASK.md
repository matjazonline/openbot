## Architecture decision 02WR-P03-D1 / r1 (proposed; no dependent edits)

1. **Reviewer identity.** Human/action review selectors become `{"kind":"principal","id":"<uuid>"}` or literal vocabulary strings `lead`/`reviewer`. No user selector decoder remains. Effective reviewer identity is PrincipalId; the parked row stores only principal_id. Existing person/tenant/membership/current run access checks stay authoritative. Notice eligibility loads principal→user/email/preference under current locks; SQL still derives a local snapshot_user for validating opt-out, without storing it. Views expose principal identity plus a display label, and can_submit uses the authorized principal returned by lock_decision, never compares a principal to actor.user_id. Token-allowance and channel-reply policies use pinned principal selectors too, preserving their separate timeout/token semantics; no role extension to these account-configured policy types is inferred.
2. **Published role requirements.** Add a separate RoleUseMode(model_only/tools/people), leaving pinned AgentUseMode unchanged. Compiler records People requirements for literal reviewer roles in decision.human and action approval, including model-step approval. Literal reviewer arrays and array bindings of literal items are supported. Existing `/params` reviewer bindings remain supported for pinned principals; role strings must be authored literally so a child with future/different parameters cannot select an uncaptured role. Reject parameter-supplied role strings during prepared-input validation unless the same literal role requirement exists at that version/step. Conditional/default reviewer roles are rejected at publication rather than capturing unused fallback roles. Same role+step used for both Agent and People is a publication diagnostic (the kinds cannot satisfy both); distinct roles coexist. B should challenge this explicit static-role rule against original requirements.
3. **Admission and sealing.** Closure uses a named version/step/role key; one capture may hold multiple person principals, optional agent selection. Resolve People with existing nearest-holder resolver; no holder/wrong kind refuses admission before a run. Agent SHARE locks precede all sorted principal KEY SHARE locks; the existing company serialization protocol is retained. Emit the complete canonical resolution0 set, existing frozen-source→canonical→normalized exact-set SQL guards remain mandatory. Aggregate distinct People principal IDs for each version/step; refuse >16 at admission, including statically known pinned principals. Parameter-selected pinned IDs are merged/deduplicated with captured People at park and the same effective16 limit applies then; their exact values are not known for arbitrary child runtime parameters at root admission. The selector list has a bounded structural cap of18 (16 principals plus2 roles), with effective16 checked after expansion; duplicate selectors can be collapsed by the parser rather than counted as reviewers. Agent selection consumers explicitly ignore People references. Future p04 may append sealed resolutions but agent selection stays resolution0.
4. **Parking and current authority.** A single persistence resolver merges pinned principal selectors and the run/root/version/step/role sealed People members, ordered deterministically and deduplicated. It never consults live department roles. It verifies each effective person's current run visibility before composing notices and inserting all reviewers atomically. Both decision.human and action approval use this path; token/channel-reply callers use their pinned-principal specialization. A contextless sample reports a named unresolved-role refusal rather than consulting live roles or creating real notices. Principal retirement/access loss retains existing reviewer-unavailable behavior; p04 followRole is a separate protocol.
5. **UI contracts.** Extend agent source transformation/picker with Role choices; selecting a role writes literal role and removes agent, selecting an agent removes role. Add reviewer source transform/picker for literal principal/role choices, preserving the unsaved editor source and unrelated fields; explicitly identify parameter-controlled reviewer bindings instead of silently overwriting them. Readonly preview uses the selected desk's scoped department chain and the same pure resolver, labels results “today's holders”, and states admission freezes actual reviewers. Bounded member/desk pagination, cross-company authorization, escaped labels/attrs, and progress/status feedback reuse existing UI patterns. Binding activation errors retain structured step/role and display on the binding pane. No CSS redesign planned.

Failure/recovery: fresh init migration only; discard disposable p03 DBs on incompatible schema, no production reset or compatibility paths. Failed resolution writes neither run nor partial capture; failed parking writes neither reviewer subset nor standalone delivery subset. Keep current stable refusal codes/64byte bound and bounded metadata.
