# 02WR-P04-D3 / r1 — agent notice gate contention

Architecture supplement to complete D1/r3 and D2/r2. No agent escalation notice implementation exists yet. Existing person/followed/DeliveryFailure projection uses account→company→source/event without a channel gate and is unchanged. This supplement addresses only the gate-held authority acquisition required by the future canonical agent notice adapter.

## Actual conflicting premises

- department.rs142–158 begins actual role/placement commands through agent_publication::lock_company_on; that function locks the real actor account then workflow::authority::authorize_company takes company NO KEY UPDATE (authority.rs45–61).
- The same production transaction calls department_desks::rederive_on230–274 through grant sync. It acquires the channel gate EXCLUSIVELY for settings changes while still owning company and principal rows.
- channel_gate.rs62–86 documents the exclusive/shared transaction advisory modes and sorted gate acquisition. thread::inbound::hold_channel_settings143–157 takes SHARED admission gates before its row locks and revalidates settings; canonical commit_on93–136 is required by D1 for an agent notice.
- D1.4/D1.8 require agent notification projection's gates before real account hints and company. A blocking company acquisition while holding the shared gate therefore permits a two-party cycle with the actual role writer. Blocking account acquisition can add a three-party cycle with account retirement that holds that user and waits for the writer's company.

Exact graph/source evidence is retained in graft-department-sync-gates-d3.txt, graft-channel-gate-callers-d3.txt and D3-r1-premise.txt. This is source/contract inspection, not a claimed executed agent-worker failure. Keep the existing role-writer and canonical ingress protocols; no global gate reorder or fake agent account is introduced.

## Decision

For a PRIVATE agent notification commit only:

1. Discover complete bounded route/source hints with no locks: exact case/recipient, actual existing default desk and configuration/binding/settings revisions, and every REAL account required for current run_as/routing authority. An agent principal is never mapped to a fictitious account. Reject/withdraw an actually absent/retired/ineligible route under the owning source's current-authority rules; missing identity is not permanent contention.
2. Acquire all hinted desk gates shared in their existing deterministic order, before any account/company/source/event row. Gate waits remain bounded by the transaction/statement deadline and current execution lease. The queue claim transaction already committed; no notification-event row lock is held while waiting for gates.
3. While holding these gates, acquire the sorted/deduplicated required account union with FOR SHARE NOWAIT, then company NO KEY UPDATE NOWAIT. Do not wait for either category under a gate. Missing rows are a stale/ineligible hint outcome; only actual lock contention is a busy outcome. Re-read exact route/purpose/source mappings under company and the owned accounts. No new account/gate can be discovered and acquired late; changed hints require whole-transaction rollback and bounded queue replan.
4. After successfully owning accounts and company, retain D1's company→run/case/decision→source/event fence order and current authority/clearance/default-binding revalidation. Reuse thread::inbound::commit_on for the single authenticated intended notice, with the SAME already-owned gate set. Inventory its private system-envelope/association producers so every required account/gate is predeclared; no inner late account/gate acquisition is allowed. Keep its existing provider/thread key ordering, immutable message deduplication, settings revision check and atomic message+intent+origin receipt. The actual lease is checked before fenced completion; loss rolls back all effects.
5. On NOWAIT contention or stale required hints, explicitly roll back and await the WHOLE transaction, releasing gates/accounts/company before recording deferral. Use a separate execution-fenced notification-event failure/backoff transaction, with the existing attempt cap/exponential delay and poison behavior. A lost fence yields LeaseLost and cannot change a replacement owner's work. No immediate inner retry while holding a gate, no second queue, no ordinary role-command timeout mislabeled success.

Expose an explicit Deferred commit outcome to the existing NotificationWorker, so this adapter-owned fenced backoff is not failed a second time by the worker. Record safe typed route contention/stale classification and metrics through the existing queue observability; add a bounded allowed error class when needed. Failed deferral persistence propagates as operational failure for the current owner, never a claimed committed notice. A permanent route change/retirement remains the original recipient's typed handling failure/advance under D1, not a recursively retried new case.

This changes only the new agent gate-held acquisition path. Person/control/legacy delivery paths retain their accepted ordering and behavior. Main D1 targeted default-binding zero/one root, authenticated origin propagation/suppression, complete neutral recipient sets, source visibility, explicit ack, two automatic hops/32 manual assignments/64 notice-handling-root bound, and D2 audit remain unchanged. The nonblocking account/company rule does not authorize a different account, binding, version, default desk, source, or fallback.

## Decisive verification required before B1 acceptance

- REAL role writer holds company and reaches the targeted desk's exclusive gate while a REAL agent notification commit has its shared gate: observe the intended boundaries deterministically. Notification defers via NOWAIT/backoff and releases all locks, role write commits, then fresh eligible retry delivers exactly one canonical message+intent+origin/intended root. No PostgreSQL deadlock, lock timeout accepted as business success, lost notice or duplicate root.
- Reverse order: successful notification owns gates/accounts/company before real role edit; exact captured route commits once or typed settings/route withdrawal wins; role edit then commits. Verify actual root/binding/revision and ordinary user multi-binding fan-out unchanged.
- Three actual claimants where a real needed run_as-account retirement/update holds the account and waits for the role writer's company: agent notice must not block on that account under its gate. It defers and releases its gate, allowing both authorized writers to finish; retry rechecks current authority and records delivery or original-case route failure honestly. Do not substitute prefix-only rollback for a promised retirement commit; qualify actual unsupported retained-data cases separately and retain D1's full owner teardown obligation.
- Competing actual notification workers, lease loss while waiting/deferring, stale hints, genuinely missing account/route and poison-batch iteration show finite attempts/backoff/no immediate reclaim, one source receipt, no extra provider/root and no client-forged origin/binding. Test that worker sees Deferred once without double-charging/failing the event.
