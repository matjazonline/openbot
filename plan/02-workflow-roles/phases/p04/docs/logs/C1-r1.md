## Proposed disposition

1. No current legitimate production application-preparation RoleAdmissionRefusal producer exists before PreparedAdmission. Mark that conditional D1.3 consumer as not applicable in the current producer inventory, rather than introducing an unused port or escalating scripted samples/authoring validation.
2. Keep every actual prepared-admission role refusal at its current fenced persistence owner, with no fake run/manifest and one canonical definite outcome/case. Current and remaining manual/message/schedule/role kinds/replay/lease/authorization tests remain required; this clarification accepts none of the unfinished behavior.
3. Scripted samples retain their honest context refusal and never create durable escalation cases. Existing pure preparation/sample assertions stay unchanged. Do not exempt actual runtime step preparation/failure AFTER admission: those are real run outcomes and remain in D1's terminal/authored-handler/child propagation coverage.
4. At p05 and when plan03 changes admission routing, re-inventory actual producers. If a legitimate role refusal is moved before the persistence owner, it must gain the original purpose-specific fenced revalidation/atomic outcome path before being enabled. No future implementation may rely on this current not-applicable disposition after introducing that producer.

No new schema/API/concurrency/authorization protocol is proposed. The original actual trigger scope, current authority, source fencing, recursion suppression, two-hop/16-recipient/32-manual bounds, D3 gate contention rules and all full B1 evidence obligations remain unchanged. No new feature is deferred. B must challenge the producer inventory and reject this disposition if a real pre-PreparedAdmission role-refusal path exists.
