# 02WR-P04-D2 / r2 — retirement audit ownership correction

Architecture supplement to accepted complete D1/r3, not an implementation or intermediate batch review. Original04B.4 requires principal retirement to clear held roles and append administration audit in the SAME transaction. D1.7's phrase “existing administration audit” has no suitable repository producer: init schema defines only binding_audit_events, whose binding_id/action/transport constraints are specific to transport binding changes. Graft/source inventory and exact schema excerpts are retained in D2-r1-premise.txt. Do not invent a transport binding or misuse a workflow run/decision to hold this audit.

All D1/r3 semantics, authority/account-before-company rules, lifecycle refresh obligations, explicit user dispositions and original AC1–7 remain. This supplement owns ONLY the audit fact and its lifecycle production. No audited retirement extension has been implemented. Partial follow/notification work is frozen for this gate and is not claimed accepted.

## Decision

Add purpose-specific department_administration_events to the init schema, owned by company (company FK with cascade on complete tenant deletion), with immutable bounded historical facts for each actual role cleared by principal demotion or deletion. Record event UUID, one retirement-operation UUID per principal transition, historical principal UUID/kind/display label, historical department UUID and explicitly bounded label representation, role, typed transition (demoted or deleted), explicit system provenance and creation time. The system records an observed retirement; it does not impersonate the affected account as the administrative actor or claim an unavailable authenticated caller identity. Ordinary role assignment/clear remains unchanged and is not mislabeled retirement.

Principal and department IDs/labels in these rows are HISTORICAL SNAPSHOTS, like existing reviewer principal/label facts. Do not add a live FK that prevents physical principal retirement or newly prevents an otherwise permitted department deletion. Tenant provenance is proved at insertion by the actual company-scoped department_roles row joined to its department and principal. Composite company predicates apply to every join. No cross-tenant or nonexistent role snapshot can be inserted. Current principal/display snapshot is read before physical deletion (or from the actual demotion transition). IDs do not confer authority and are never used for live selection or routing. Keep existing captured-department deletion refusals for manifest/context/escalation references unchanged.

Use the actual PostgreSQL principal lifecycle boundary, rather than relying solely on public Rust wrappers: augment the existing department_principal_demoted cleanup before it deletes role/membership facts and add a BEFORE DELETE principal hook so FK cascade cannot erase the source first. Snapshot all held roles in a set-based INSERT SELECT, then preserve existing role/member/grant cleanup. Emit one audit row for each actually held role; a nonholder produces zero. The existing company-serialized application retirement owners remain responsible for final synchronous followed-decision refresh AFTER all membership/principal changes. Audit creation never acquires user accounts after company and never invokes role assignment, lead provisioning, or refresh from a row trigger while principal/member locks are already held. Raw demotion/deletion gets the same audit facts; production lifecycle paths get the complete refresh/notice/cancellation protocol required by D1.

Audit insert guards take NO company or user lock from inside a principal row trigger. Production owners must already hold company NO KEY UPDATE before principal/member mutation under D1. Raw SQL concurrency fixtures take that same company lock first; a sequential bypass fixture may exercise guards without pretending it proves the production lock prefix. The audit insert uses only existing FK-compatible company identity and lock-free source/snapshot validation; it never upgrades company after holding a principal. Require the nested retirement-trigger path (not a direct insert/GUC/client flag), validate bounded shape, role vocabulary and actual company-scoped role/department/current-label representations before source cleanup. The demotion constructor uses OLD.kind with the actual current last display label; deletion uses the actual OLD record. The PostgreSQL trigger nesting guard plus the sole actual producer and material-clear check is provenance, not an authority grant. A deferred check requires that exact held role to be absent at commit, so an arbitrary audit insert without the material clearing cannot commit. Snapshot facts are immutable; update/upsert replacement/direct delete fail while company survives. Complete company deletion may cascade them. A unique company+operation+principal+department+role key prevents duplicated facts within the actual retirement operation. A transaction rollback removes audit and role changes together. Repeating already-completed retirement of a nonholder makes no spurious audit. No fabricated account/person/department, no automatic appointment, no backfill/compatibility or second queue.

Work is set-based over the roles already being removed by the lifecycle, with bounded per-row data (4 KiB maximum, actual principal label byte bound, the explicit D2.2 department snapshot representation and fixed role/transition enums), no unbounded Rust collection or aggregate JSON. Existing transaction statement/deadline limits apply. Current follow refresh still uses the indexed at-most256 pending decisions/company and <=16 reviewers; no historical scan is introduced. If an audit reader is added, it uses existing owner/admin company authorization and bounded keyset pagination; no additional UI/API is required merely to replace the incorrect assumption that a generic audit store exists.

## Verification before B1 acceptance

- Actual production member removal, account removal (including owner of the workflow tenant), agent deletion and direct principal demotion/deletion clear all held roles and produce exact one-row-per-role audit snapshots in the same transaction. Same UUID/name in another company cannot appear. No holder/no-op retirement creates no audit. Failed final statement rolls back roles, assignments, notices and audits.
- Delete a historical principal and then an otherwise deletable department: audit snapshots remain complete/immutable. Captured context/case departments still have their existing retention refusal. No live authority is recovered from audit IDs.
- Direct cross-tenant/nonexistent/fake role event and an event whose role was not cleared fail at the appropriate insertion/commit boundary; update/delete/upsert cannot rewrite an event. Full company teardown commits and cascades its audit rows.
- Existing both-order retirement/role/vote/projection races from D1 remain required, with real final refreshed reviewers and actual notice cancellation; audit is not a stand-in. Scoped deferred action-identity fix must still prove full owner retirement commit and orphan/wrong-identity rejection.

B reviews this supplement against the originals and actual schema/callers, including historical-identity FK exception, hook ordering, source proof, company/account ordering and complete lifecycle reach. No source implementation review/PASS is requested at this gate.


## D2.2 F1 correction — bounded, explicit department-name representation

Department names are unbounded nonblank text in both actual production normalization and schema. Preserve that producer domain. Retirement never depends on adding a new department-name limit, and the audit event cap stays 4 KiB.

Store each department label as an explicit snapshot representation: `prefix` contains the first **128 Unicode characters** of the actual current stored department name, and `truncated` states whether a 129th character exists. Store the full actual company/department/principal UUIDs and role; the label is display context, never identity or authority. The immutable record does not claim that a truncated prefix is a complete name. No digest or whole-name copy is needed. Current principal labels are stored exactly under their actual existing 255-BYTE bound. This avoids making an arbitrarily long otherwise valid department name prevent role/member/agent/account retirement.

Use one immutable SQL helper for the representation, equivalent to `jsonb_build_object('prefix',left(name,128),'truncated',char_length(left(name,129))>128)`. The actual retirement producer and insert source-proof guard invoke that same helper; they do not independently implement the clipping rule. The guard compares both fields exactly to the actual company-scoped department source. This guarantees valid UTF-8 boundaries, at most512 UTF-8 bytes in the department prefix (at most768 JSON-escaped bytes for 128 control characters), and explicit truth about truncation. The static event shape, bounded exact principal label, fixed identity/enum/provenance fields and this representation fit the unchanged 4 KiB whole-event bound. No unbounded Rust collection/JSON/name copy or new source-name validation is added. A reader accepts the explicit representation, escapes the prefix, and clearly marks `truncated`; it never renders it as a claimed full historical name. No existing department producer, picker or label consumer changes its domain or display behavior.

Add discriminating actual production create/update-name→role→retirement cases for 127/128/129 ASCII characters, multibyte names across the same character boundary and >512/>4096 UTF-8 bytes. Assert retirement commits, exact IDs/role/label prefix+truncated flag, whole-event <=4 KiB, full principal label retained, and source department name unchanged. Include maximum JSON-escaping/control-character name and principal-label cases so character, byte and encoded-row bounds are not confused. Source guard negatives must reject forged prefix, false/true truncation flags, rekeyed/foreign department or principal and mutation/upsert attempts. These supplement, not replace, all D2 original production/no-op/rollback/tenant/deletion and D1 retirement/concurrency obligations.

Cascade/re-grant qualifications retained from independent R1: if company deletion has already removed the company or source roles/departments, the row hook creates no replacement fact and does not rely on sibling cascade order. Complete tenant deletion cascades its history. Deferred role absence checks only the transaction inserting that retirement event; later separately committed legitimate invitation/re-grant does not revalidate or rewrite historical events. Reconstituting the exact audited role in the SAME retirement transaction remains rejected by material-clear proof. Raw bypass concurrency fixtures take company before principal, and nested audit triggers acquire no late company/user lock or refresh/provisioning work.
