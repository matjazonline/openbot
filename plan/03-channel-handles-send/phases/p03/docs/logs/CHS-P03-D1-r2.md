## 1. Two durable facts, with one final decision

Use a bounded immutable terminal proposal per execution for the validated business output and, for automatic reply, canonical projected content, original C001 source/context link, run actor/sender/policy evidence and integrity digest. The proposal stages a completion; it is not terminal success and is not a delivery record. Use a separate final decision unique(company,owned root run), tenant-qualified to channel_reply_runs and that actual terminal execution. An automatic decision references its immutable proposal; a suppressed decision carries no publishable content/action. Unique identities reject conflicting content/reused keys and replay the exact stored decision. Only the authentic designated-root link participates; passive contexts, observer/manual/scheduled/child/sample runs create none.

Write the final decision in the existing shared completion transaction, alongside execution output/disposition, run progression and job/attempt settlement. Suppression still validates business output, skips projection/action/approval, and writes explicit suppressed decision atomically. Normal automatic output must satisfy the frozen channel contract before success. A rollback leaves no terminal success or final decision. No delivery/provider acknowledgement participates in business success.

### Exact staging and continuation witnesses

- Pure stage: retain/lock the actual pending, due, unleased and nonexhausted job, then park it through its existing pending-job transition; no task attempt exists or is invented.
- Fenced stage: retain exact worker/generation/attempt/lease-expiry witnesses and close/park that actual attempt under the current bounded commit guard.
- Parked stage: carry the actual accepted/completed source wait ID into CompletionOwner, not an unqualified Parked flag. Validate company/run/execution, source-wait completion/provenance and closed job, then register a distinct final-approval wait occurrence on the same execution. A completed child/event/effect/business wait and the new live approval wait remain separate history; only one live wait exists.
- Recovered final-error handling cannot stage a success decision. It retains existing error routing.
- Approved resume: a dedicated continuation witness binds the frozen proposal, matching formal decision/digests and reopened pending job/continuation count. It completes saved data under that owner, not an IO fence, and cannot call the original handler. Preserve active STEP/model-tool claim guards and add explicit staged-finalization exclusion. Replays/uncertain commits observe the final decision or pending proposal by stable identity first.

Adapt existing protected-action decision shape/guards only for this typed final origin and these real witnesses; ordinary action approvals retain their exact fenced-attempt requirement. No nullable-witness catchall or permissive trait default. Formal approval still uses current authorized/revision/digest-checked submission; plain messages/comments cannot approve. Final proposal and final decision uniqueness, immutable data and ownership/transition guards remain database-backed.

## 5. Publication queue contract, without a second delivery state

An automatic final decision owns only canonical publication work: pending, claimed, published receipt or terminal publication failure. Suppressed decisions are never claimable. Add bounded durable polling/claim/settle operations with database uniqueness, generation/worker/expiry fencing, attempts/backoff and diagnostic codes, following message-intent conventions. Proposed bounds: page1..64, lease30s, max8 publication attempts, bounded lock/statement time; fair per-company selection and retry scheduling prevent a poison batch from being immediately claimable again. Replays use stable decision/publication identities; an unknown transaction outcome is observed by identity before retry.

A claim confers publication authority only for that immutable successful decision. It is not WorkflowFence. Lease expiry permits a fresh claimant; stale generations cannot settle. Store canonical message/delivery linkage when publication later commits, and read transport status only from the existing delivery queue. Local publication has a local receipt with no invented external send. p04 implements the shared route/planner/publication transaction and supervised draining; p03 provides the durable bounded work contract, not an in-memory callback owner.
