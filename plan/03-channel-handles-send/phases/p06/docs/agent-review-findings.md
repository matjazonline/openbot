## CHS-P06-AG1-F1 — typed native response schema does not cover retained rejection and early-end routes

[Task](TASK.md), [review](REVIEW.md), [note](agent-review-notes.md#chs-p06-ag1-r1--architecture-gate-changes-required).
- Classification: **actionable, high, correctness/requirements; OPEN**. Origin is the proposed decision's incomplete terminal-path adaptation, not implemented p06 code.
- Decision evidence: D1/r1 §1 makes the native root output a response object with required body while retaining the existing editable decision.human gate; §2 preserves custom slots and proposes a trailing finish_response mapping to prevent unrelated custom output becoming the response.
- Actual contract: `templates/agent_workflow.rs:228–255` maps the built-in review choices to approve→next and **reject→$end**. `decisions.rs:318–329` constructs the decision output as `{choice,data,feedback}`, then `batch.rs:120–140` validates that entire value against the root output schema whenever the selected target is End. `adapters/persistence/workflow/decisions.rs:537–559` performs this preparation before writing the submission; validation error rolls the transaction back and leaves the decision open. The wrapper has no top-level body. Therefore under the proposed required-body root schema, ordinary reject cannot be accepted. The approve path reaches the new mapping and works; it does not fix reject.
- Adjacent terminal paths that the correction must account for: the current composer explicitly preserves custom `$end` (`agent_workflow.rs:257–269`), and the existing representative BeforeReply rule uses hold→$end (`agent_workflow_tests.rs:57–65,111–125`). Such a short-circuit wrapper also fails the new root schema. An explicit AfterReply `$end` bypasses an appended finish_response, so a schema-valid unrelated `{body: ...}` can become the automatic reply unless that branch is deliberately handled. Appending a tail alone only repairs `$next` fallthrough. These are observable existing routes, not malformed inputs.
- Impact: the default reviewed assistant can reject valid rejection commands indefinitely until timeout. Custom intentional early termination can turn into invalid-output failure or unintended automatic response instead of its intended stop behavior. This violates the requirement to preserve private review/custom communication while avoiding accidental final sends.
- Required revision: specify coherent terminal behavior for reviewed reject and supported custom early-end paths under the typed native business output and automatic responder. Rejection must be accepted as a real decision and must not publish the rejected draft; it cannot rely on output-validation failure to stop work. Define which custom End branches retain saved response versus intentionally terminate without response, or are rejected at authoring with a clear contract. Preserve schema-valid business output and trusted suppression semantics; do not relax validation or infer suppression from payload flags. This finding requires an explicit behavior decision, not any particular implementation authored by B.
- Required focused verification: execute the actual native reviewed reject submission through its durable decision path, asserting closure/outcome and no automatic/customer response; test approve with edited data separately. Exercise BeforeReply hold→End, explicit AfterReply End with unrelated schema-valid output, normal AfterReply fallthrough, and final channel.no_reply under unchanged budgets. A compile-only example check will not catch the runtime reject failure above.
- Verification status: static architecture analysis of actual source/callers, no source edits or runtime diagnostic. The proposed dependent implementation has not begun, so no claim of observed new-code failure.
- Instruction lesson: when tightening a template's root output or installing an automatic responder, enumerate all terminal routes, including private decision rejection and custom explicit End branches, rather than inspecting only the normal success tail. This is a candidate review rule supported by the cited retained branches; no instruction files changed.
- Resolution history: 2026-11-07 OPEN against exact D1/r1; awaiting revised immutable decision and recheck.
