# Request trace fields and sensitive routes

The central HTTP request span is an allowlist. It records a generated request ID, HTTP method,
protocol version, and a static route template only when Axum supplies a matched template; an
unmatched request has no route field. The span never falls back to the incoming URI,
path, query, `Host`, cookies, authorization headers, or body. A dynamic path segment is data, even
when it looks like an internal identifier. Request IDs are generated by this application and are
not copied from caller-controlled headers.

## Route inventory

| Route family | Sensitive or caller-controlled values | Safe trace label |
| --- | --- | --- |
| `/auth/google/{register,login,connect}` and `/auth/google/callback` | OAuth redirect state, callback `code`, `state`, and provider error query values; flow cookie | `oauth.google` and outcome, never the callback URI |
| `/auth/apple/{register,login,connect}` and `/auth/apple/callback` | Callback form `code`, `id_token`, `state`, optional user data; flow cookie | `oauth.apple` and outcome |
| `/webhooks/email/resend_api/{token}` | Per-account webhook token in the path, Svix signature headers, and provider payload | `webhook.resend_api` and outcome |
| `/webhooks/email/sendgrid` | Signature headers and inbound message body | `webhook.sendgrid` and outcome |
| `/login`, `/register`, `/api/{user,json/user}/{login,register,register/confirm}`, `/ui/profile` and its password/change routes | Passwords, confirmation codes, addresses, and session cookies in forms/JSON/headers | Static route kind and status only |
| Company integration and MCP settings routes, including `/ui/companies/{company_id}/resend_api` and its `/token` operation | API credentials, connection tokens, and configuration forms | Static route kind and opaque internal IDs only after authorization |
| Query-bearing mailbox, delivery, notification, schedule, workflow, library, team, and dashboard pages/APIs | User-selected filters, cursors, search-like terms, and object selectors in query strings | Static route template and bounded outcome only |
| Unknown, malformed, and future signed-link routes | A path or query may itself be a bearer secret | No raw-target fallback |

The current router has no bearer signed-link endpoint beyond the Resend token path. Any new
signed-link endpoint follows the same no-raw-target rule. Ordinary object IDs in paths remain
excluded from the central span, so a future route cannot silently make them log fields.

## Operational events

For triage, emit explicit provider type, bounded outcome/status, latency, and opaque internal
correlation IDs where the handler already has them. Keep account, company, delivery, and request
IDs scoped to events that need them; never derive a label from arbitrary path/query/form text or
provider response bodies. Auth admission metrics use fixed route-kind/outcome dimensions. Logs
must not become storage for OAuth codes, webhook tokens, credentials, or signed links.

The application writes structured logs to the platform sink. Incident response assumes restricted
log access and a deployment-defined retention period; the app does not enforce retention. The
Fly ingress proxy or another upstream component may keep its own access logs before these spans
exist. Operators must inspect that access-log format and redact or omit request targets and
credential-bearing query strings there as a separate deployment control. Application redaction
cannot sanitize an upstream log after it has been written.
